# 已消费教师数据的跨来源重复检查

本阶段只比较此前已封存的两份教师训练档案与新多教师数据，不训练、不运行模型前向、不启动游戏，也不读取未使用留出种子清单。旧档案固定为此前已接受来源中的 2,253／2,851 组，共 5,104 组、322,151 个候选；新数据固定为已消费训练 59 组、开发 62 组。旧档案身份从固定 Git 提交中两份已消费训练来源的封存收据提取；其中旧收据可能包含按已消费训练 seed 分组的计数，但入口只提取具名摘要，不解析或输出这些计数。两来源的最终接纳关系已在此前兼容性检查中复核，本轮不重新打开可能含保留值的历史登记。新数据须重新通过本地 `load_trainable` 数据门核验，该来源认证会解析已消费比赛的角色元数据。基线 checkpoint 只提供已认证的 schema、mean 和 scale，seed 不输入比较器。

对每个新组，分别在两份旧训练档案中检查：完整有序候选组的原始 float32 表示，及使用相同基线归一化后的 float32 表示。正负零规范化；先用 SHA-256 缩小候选，再逐字节比较，不能只凭摘要判同。候选顺序、共享特征与每个候选的数值都参与；只比较同一有序组内的教师目标**索引**。若某组既匹配相同标签、又匹配不同标签，记为冲突；否则分别记为同标签或无匹配。每种表示在训练／开发两侧单独计数，每个新组只计一次。

此检查只报告**旧来源与新组的直接重合**，不做数据删除、旧来源内部冲突检查或跨 raw／normalized 的传递闭包；也不证明完整游戏状态相同、不同种子彼此独立或教师动作实际执行。若未来要混合训练，仍须按冻结规则处理全部来源的闭包和冲突，不能以本报告代替独立比赛。

归档逐个扫描：在同一个已打开文件描述符上先后核对完整文件摘要，先检查 ZIP 成员及 NPY 头，再只解码共享特征、候选特征、偏移与教师标签四个训练数组。其余 `ops`／`seed` 不解码成数值；整个文件哈希及 ZIP 内部缓冲仍可能读取其 payload 字节。逐组处理，不构造旧来源全体候选的 373 列展开矩阵；宽度超过 256、无效偏移、超预算或任何身份不符均停止，不截断或补组。每份档案最终复核成功前的回调结果只是临时内存，不封存。

来源、关键源码、基线身份和数据切分须在比较前绑定并提交推送。只允许一次 Windows Job，启动时可用物理内存至少 5 GiB，运行采样下限 4 GiB；Job 采样 RSS／commit 上限 2／3 GiB、工作时限 900 秒，磁盘余量至少 4 GiB。资源与时钟均为采样或协作式限制，不是硬实时保证；异常保留现场、不重试。个人路径、档案摘要、原始数组和 seed 不上传，公开结果只含匿名汇总。事前本地提交不冒充第三方时间戳。
