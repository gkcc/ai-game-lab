# 两臂任务 BC：单次真实训练结果

事前登记 [`8ebbae2`](../task-pair-wsl-training-v1-20261030/registration.json) 并核验远端后，只发起了一次训练尝试。调用方实际观察 Windows 包装进程退出码为 0，包装程序原样传递 host 的退出码；host 报告技术状态通过、WSL 子进程零退出、已绑定 Linux 会话清理通过。规范的子进程原始令牌收据、启动记录、监督状态和调用方事后写入的观察记录保存在本机；host 原始标准输出仅在会话工具记录中，未单独封存。独立子代理核对了 nonce、令牌、合同、清理标志和收据之间的一致性。进程间管道不认证写者 PID，本机记录和 Git 提交也不是第三方时间戳。

经认证的程序报告两臂各完成 64 次、每批 256 组的更新，单独计算的辅助项梯度范数超过登记阈值的更新不少于 32 次，两臂均相对初始权重变化且彼此不同。入口要求唯一可见 JAX GPU 与事前固定设备名称一致，逐叶检查参数、输入、梯度及优化器状态所在设备和有限值，并同步完成反向计算及更新。操作方在运行前以驱动查询再次核对了事先固定的设备身份；因此这是受审程序对实际 GPU 更新的证据，不只是设备可见。两次独立的 WSL `nvidia-smi` 进程匹配探针均未匹配到训练进程；采样时机和进程映射可能影响它们，既不能将其当作 GPU 未使用的证据，也不能声称已有独立的进程级 GPU 活动确认。探针原始输出仅在会话工具记录中，操作方本机记录的是事后摘要；没有做 CPU/GPU 速度对照。

三个模型文件由原 `TaskNetwork(path, sha)` 重新加载；独立子代理在 CPU 上再次检查本机摘要、参数、归一化、schema 和两臂来源元数据，使用合成输入核对直接评分与分块评分。操作方记录旧原始 checkpoint 与本次基线副本均匹配预先冻结的身份。操作方首次只读核对时误用 Windows 规范化路径检查，导致验证脚本抛出 `ValueError`；该错误由操作方观察，原始脚本与日志未单独封存。修正为检查清单原始相对路径后，重新只读计算的身份一致；操作方记录该检查仅读取且未重跑训练。事后摘要一致不能排除期间的瞬时替换。

登记的开发筛查为 **failed**：三个来源的未重合 `PLANT` 同目标工人 top-1，辅助臂相对控制臂的等权平均变化为正，但不足预定的 +1 个百分点；每个来源的 −2 个百分点下限和两项护栏均通过，程序保存的所有必需项支持标记均为 supported。父启动器及独立子代理从已保存的指标分别复算筛查算术，没有独立重算各簇组数或重新预测开发样本；精确指标与模型摘要不发布。三组数据此前均已消费，`unseen_train` 仅表示未与已绑定训练组数值重合，不能称为独立比赛或统计上可信的竞技提升。

独立子代理的附加合成测试发现：`TaskNetwork` 接口允许不同 ID 搭配相同特征行，该次探针观察到批量浮点计算对重复行产生不超过 `1e-12` 的微小分数差，这不是跨环境的普遍误差上限；代码只保证实际 logits 精确相等时 `argmax` 取首项。该测试的直接评分与分块评分一致。固定候选编码把 unit、目标坐标和操作写入特征；历史预检对各来源验证了身份顺序与操作编码，本次没有独立重读各来源数组。这个合成反例不能证明本次开发筛查或真实对局发生分歧。
