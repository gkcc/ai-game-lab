# 新 control 任务头：单场已消费角色技术验收登记

本阶段拟使用上一轮真实训练后冻结的 `control` 任务头、既有冻结作物头和终局施肥教师对手，验证已保存权重是否能参与一场官方完整对局。它不是新训练、独立留出评估、胜率比较或教师晋级；不得据一场结果声称竞技收益或模型泛化。完成的旧模型对局与离线反转探针不自动证明这一新任务头的能力。

固定历史正式面板中已消费的 `S01`、教师对手和 0 席，一次尝试、最多一场，本轮仅作开发诊断；先核对历史已接纳记录及本机种子映射。现有通用 `Panel` 的结构名称只是适配占位：本阶段内部 `S02` 对应实际历史 `S01`，内部 `market` 对应冻结教师；内部 `S03` 用未执行的历史 `S02` 仅满足结构约束，其他占位角色均不执行比赛。这既不是恢复失败的 S02/S03 对抗面板，也不是续跑失败的玩具实验。若角色、模型、对手或历史身份不能认证，停止并保留现场；不生成替代种子、不换对手或继续补赛。历史角色已消费且不保证与未指定的所有私人实验不重复。

沿用原游戏推理限额：任务头 4,000 次、作物头 8,000 次、共享输入 160,000 行，另有原单回合和控制器上限。失败的玩具轨迹只提供局部工作量描述，没有下一回合和现场堆栈，不能据此调整限额。新任务头使用既有 CPU 推理路径，本阶段不训练、不证明 GPU 加速；官方规则、冻结教师、模型、默认 Bot 和历史证据均不修改。

场前冻结源码、规则身份、对手和本机模型身份，独立登记资源及时间上限。公开来源和限额核验后，父进程在读取私人身份之前排他建立一次性尝试标记；子进程在读取私人身份之前排他建立启动标记，之后核对并消费单场授权。已存在失败标记时拒绝进入。资源、身份、执行、复演或收据条件失败即停止且不重试。父进程计时从其 Python 快照入口开始，认证、私有绑定前及绑定期间、预检与返回前检查计入后续采样额度；解释器启动本身不在其中，父进程各阶段没有独立硬截止。子进程使用自己的快照起点，正常父入口启动的子进程另受 Job 时间约束；两者不是跨进程同一个绝对硬截止。授权标记不认证子进程是否真的属于该 Job，也不能证明父进程始终存活；同用户并发抢先消费标记时不保证资源隔离，应独占运行。尝试标记建立后的失败会尽力写独立失败收据，写入失败时保留标记并将结果视为未知。本地标记不是第三方时间戳，也不阻止同用户并发篡改。

旧驱动失败收据中的 `completed` 表示已通过验收的场数，不证明未验收的比赛没有启动或没有执行；实际执行状态须结合进程监督和本地产物判断。外层失败收据对无法确认的接收场数保留未知，不猜为零。

若尝试标记因普通 I/O 错误而无法创建，入口会尽力写单独的失败收据；标记已存在或并发归属不明时直接拒绝，不认领他人的标记。磁盘或权限同时阻止标记与收据时，无法保证留下持久记录。操作方仍须记录失败并停止，不自动重试；在标记创建前，入口不读取私人角色或启动比赛。

必须通过真实官方引擎与既有保序复演：720 个状态、719 次双方动作、双方 `DONE`、零 Agent 错误，核对规则版本、逐步状态和背包顺序、结算及受管 Job 退出；真实任务头与作物头前向计数均大于零。外层还须核对协调器已返回的独立标记和入口自然零退出，不能只凭退出码接受（例如 `SystemExit(0)`）。仅在这些条件全部通过时称完整官方对局通过。计数与复演来源应分别说明，不能把同一重构计数当作两份独立现场测量，也不能仅凭调用次数证明不同权重改变了完整请求。

新增诊断只在本次专用子进程的真实官方游戏执行区间观察经认证的原预算器 `forward` 和 `controller`，不覆盖 `gate`；调用结果、计数、异常及原策略必须保持。只保留白名单事件、允许的固定原因和异常是否原样传播至旧 job 边界；该关系不代表外层 child/Job 抛出同一异常。记录可能为 unknown，事件不等于游戏最终失败原因，未观察到拒绝也不能证明未覆盖方法没有拒绝。诊断不写入原 Worker 的游戏写预算，退出该上下文后才尝试保存独立本机小收据；写入失败不能覆盖原比赛异常。游戏执行区间内捕获的 `KeyboardInterrupt` 尽力穿过旧包装重新抛出，游戏前后取消或强杀的传播不作同样保证。被强杀、目标实例不唯一、回调不在同进程或缺少可信现场事件时，仍应报告未知。诊断不可将状态、候选、种子、路径、模型身份、异常文本或原始堆栈公开。

观察器为预算调用增加一层 Python 包装，会产生非零运行开销；官方超时依赖实际耗时。合成微测不能代表完整比赛，因此若发生临界超时，不能断言未安装观察器时也会超时。
