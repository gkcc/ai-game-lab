# 玩具模型官方 Worker 冒烟登记

本阶段单独验证官方 Worker 的真实运行链，不续跑已失败的 24 场历史开发面板，也不用于竞技比较。两份任务头和一份共同作物头均由公开特征 schema 与固定公式在本机生成，没有读取或训练用户模型；第三份任务头只满足现有 Panel 的结构要求，不参加比赛。

旧面板登记固定于 `b97687f`，失败记录固定于 `eb20f60`；新入口会核对它们是登记提交的祖先，并检查对应历史文件与原提交字节一致。新冒烟不能改变旧面板的失败状态或把结果补入旧账本。

固定两场：同一个公开合成种子、同一个冻结市场对手、同一席位，分别使用正、负方向的玩具任务头。底层 Panel 复用的 `S02`、`S03`、`market`、`round2` 只是本实验的结构占位，不能解释为先前历史面板中的身份；其中 `S03`、`round2` 和第三任务头不执行比赛。合成测试种子来自现有公开单元测试，不作为独立留出集。新目录与旧失败面板分离，不修改旧状态或原始产物。

登记前以不显示私有数值的方式检查了本阶段明确指定的四份受保护种子文档，两个合成占位值均不与其中的种子相同；未扫描其他未知留出集，因此不声称对所有历史数据均无碰撞。

登记提交后，先在隔离进程中验证源码、规则和两份公开 schema；按固定公式生成模型文件，并经实际部署加载器验证同一合成输入下两个任务头的选择不同。然后通过现有 Windows Job 监督器与 Worker 顺序执行两场，分别检查 720 个状态、719 次动作、双方 `DONE`、零 Agent 错误、官方逐步复演、请求重构、背包顺序、现金闭合、进程退出与 Job 清空。只比较两场已经保存的共同历史前缀；若对局中没有可比较的模型选择，应报告未知，不能凭空推断权重无效。

每场的模型、逐步状态、trace、回放及详细收据留在本机。公开结果只可包含技术状态和白名单汇总；比赛得分不作为收益改进或显著性证据。两场均使用 CPU 运行既有 NumPy 推理，不能因此声称新增 GPU 训练或加速。

固定一次尝试、最多两场和一次回放比较；认证通过后先排他写入本地尝试标记，任一资源、执行或验收条件失败即停止，不自动换种子或重试。认证失败时尚不创建标记，也不进入比赛。底层通用驱动的启动收据可能写入容量 24，那是驱动可容纳的上限，不改变本登记的两场范围。进程资源和总体时间由既有机制采样，父进程比较不具备独立的操作系统硬内存上限。本地标记与登记不是第三方时间戳，也不防同用户恶意并发替换。

每场由父进程写入独立授权标记，子进程进入 Worker 前排他消费；已消费的单场不能再次进入。这些文件不能证明父监督进程在每个瞬间仍存活，也不能阻止同一用户在授权写入后、消费之前恶意抢先调用。
