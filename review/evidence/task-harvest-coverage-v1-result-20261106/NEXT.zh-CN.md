# 下一步：未表达原地收获的受控官方探测

独立规划子代理只读核对冻结教师、TaskAgent 和现有恢复核心后，建议优先验证未表达的收获机会。维护者采用这一方向，暂不优先追逐那个单独的远程派工实例，也不再为已经请求覆盖的 271 个地块制作标签。

理由是候选生成确实受首选成熟年龄、肥效、继续浇水等经济条件约束，而选择网络只能返回 lookup 中已有 ID。等待也可能正确：非持续作物过早收获会结束该株生产，可能放弃之后的增产。因此 1,606 个机会只是表达范围证据，不是损失估计。

## 先固定点，再验证真实恢复

下一阶段另行冻结新代码、统计口径、资源预算和门槛。仍用四个已消费来源、240–648 窗口，每源仅选首个满足以下条件的点：首 callback 时单位可用、静态条件允许原地作物收获、自己的 HARVEST 整回合未表达、全回合同地块没有最终 HARVEST 请求。顺序须事前固定；缺失保留、不补抽。**当前只有本轮计数，尚未证明四源各有合格点，也未选定这些坐标。**

每点两臂各重新构造原学生和冻结对手，从第 0 步输入各自合法历史观测，重算并核对请求、稳定 trace 与累计预算。不得直接修改 previous、清零预算或重放旧未来对手动作。恢复官方状态必须保留 configuration、info 和步号。

事实臂先连续执行 48 次动作并复现原请求、状态、背包及仓库顺序；通过后才允许干预。已有单步恢复证据和本轮元数据结果都不能代替这个真实验收。

## 只替换一次实际提交请求

旧 HarvestSelector 强制要求已有候选且与原选择同单位，不能直接评估这里未表达的动作。新增很薄的离线请求适配：目标回合照常运行、计费原网络和控制器，完整保留原请求及原 trace 意图；在另外记录的实际提交请求中，仅把目标单位动作替换为 `HARVEST` 一次。其他单位动作和所有市场订单的内容、数量与顺序保持不变。随后双方按新分支合法观测重新决策。

不能把原 trace 的选择记录或 unit_request 改写成“模型主动选了 HARVEST”。原意图、一次请求替换、官方实际执行与结果必须分开记录；离线适配不作为新 Bot 发布。原模型、策略、默认 Bot、旧 core 和规则保持不变，复用恢复、计费、保序比较与受控 Worker，不另建 Server 或训练平台。

## 规模与结论边界

最多四点、八臂、384 次官方转移，环境构造另计；事实臂承担复核，不追加未计数复演。所有模型／控制器的历史前缀和后缀仍计入既有每臂及阶段预算。零新种子、零完整比赛、零训练，不根据结果追加点或寻找正例。

保留实际收获执行、作物是否移除、两臂 48 步双方现金，以及背包、仓库、种子、存续作物的端点。未售库存不估价入账；仍未兑现的生产或种植窗口和 48 步截断均需说明，不能等同于终局净收益。

这个实验只判断此前不能表达的动作是否产生可辨识的经营差异。技术检查和信号门须在读反事实结果前另行冻结；无论正负都结束并保留。即使有正向现金变化，也只支持进一步研究，不能据四点直接生成正式训练主标签、发布策略或宣称 BC/PPO 已准备好。

本文件仅记录下一阶段建议，当前未实现请求适配、选择新点、执行官方分支或训练。
