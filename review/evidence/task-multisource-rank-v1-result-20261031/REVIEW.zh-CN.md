# 独立复核与证据边界

两名独立子代理分别调用封存读取入口，检查事前登记、单次 attempt、Job／worker／owner／claim、私有模型快照、覆盖及精度转换收据之间的绑定。Job 分配、恢复、退出和清理字段通过；8 次完整资源采样均满足登记限制，但采样不是硬实时资源上限。

一名复核者按保存的匿名聚合重新计算筛查：新开发 59／62 不变且选择变化为零，两个新增效果条件失败；旧非浇水诊断 75／80 不变。另一名复核者检查 64 次 CPU 同步更新、非零梯度和权重变化的声明是否与冻结代码及运行收据一致，并核对 312 组数值一致性的范围。后者发现一个合成反例：训练使用的 float32 基线加残差首选仍可能与部署 float64 基线不同，即使本轮检查的相对残差及加回 float64 基线后的首选一致。真实样本是否出现此情况未知，不能把该项检查表述成训练与部署的完整逐组一致性。

这些是代码和本机收据的独立核对，不是重新读取示范、重算逐组前向或逐步重新训练。训练收据记录完成次数与曾出现非零梯度，没有独立逐步梯度日志；本机封存不是第三方签名或不可篡改时间戳。开发／诊断结果均非独立完整比赛，不证明真实收益，也不说明未发生选择变化的具体原因。
