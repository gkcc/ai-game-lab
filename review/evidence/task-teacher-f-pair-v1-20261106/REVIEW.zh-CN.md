# 完整配对入口的执行前独立审查

本轮新增一个独立配对入口，复用已经冻结的 F 来源适配、七阶段 Worker、官方复演、单次替换门及 NUL 兼容写入预算。没有修改默认 Bot、模型、旧策略、官方规则或原实验文件。

主代理与独立子代理先审实验设计，再读源码并运行针对性合成检查。冻结前修正了以下真实缺口：

- 除历史 Git blob 外，旧登记、证书和 summary 的当前副本也必须保持原字节；PROGRESS 须保留最新 BASE 的完整内容，不能只保留更早筛选登记的前缀。
- JSON 写入计费包含末尾换行；子进程按可能产生的三份收据预留空间，阶段前后核对私有目录与合计物理占用。
- 正常 CLI 帮助退出不能被记成运行失败，执行阶段的异常 SystemExit 仍须失败。
- 关闭上下文或写关闭收据失败不能覆盖已经发生的原始错误；原本成功时关闭写失败也不能返回成功。

新包 16 项回归由主代理全部运行通过、无跳过；包含历史保留、63 原件与八案例认证、完整 56 阶段合成父流程、真实 child 分支的合成入口、前序控制审计缺失、篡改、预算及失败保留。Windows NUL 与既有写入限额适配器在自有临时目录实际验证，目录已经删除。假 Job、合成状态及 fake Worker 不作为真实比赛证据。

独立审查者运行初版 14 项中 13 项通过、NUL 项因没有自有临时目录而明确跳过；该项由主代理另行实测。最终新增两项独立通过，并复核最后的关闭失败修复。复审未发现阻止准备、冻结与受管配对的具体缺陷，没有读取本轮真实私有来源或运行模型、官方引擎。

主代理随后实际执行 `--prepare`，退出码为零，成功绑定全部八个案例及 56 阶段。该操作只认证来源、证据与文件身份，新增完整比赛、模型前向和官方转移均为零。完整比赛验收另行执行，不能由这些测试或准备结果提前宣布成功。
