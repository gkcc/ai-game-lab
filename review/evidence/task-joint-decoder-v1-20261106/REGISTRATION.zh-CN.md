# 候选集合感知任务解码：四场已消费开发初筛

起点为 `a68c818ca4f73d7584e7ca8d1900fbe3f89cab2d`。上一轮八次单点教师替换没有正收益，因此不把那八个选择标成更优 BC 标签。本轮改为检验一个独立假设：冻结网络评分，经候选之间的竞争关系解码后，是否能改善实际任务分配和完整比赛收益。这个假设不是上一轮负结果的已证实成因。

## 策略范围

创建独立 `task_joint_decoder_v1` 候选，保持 baseline 任务网络、作物网络及原规则控制器不变。每次回调照常执行并计费一次原任务网络前向，使用该次已产生的 logits。先最大化当前候选图中可分配的单位—地块数量，再最大化分数和，精确平局按原编码语义身份 `(unit, y, x, op, id)` 定序；同一单位—地块的多个操作仅保留其中最高分、同分最小语义身份的候选。每次只返回最优匹配中最高分的一条，同分沿用上述身份次序，随后由原控制器更新资源与候选并重新计算。

最大基数是本候选的解码偏好，不能说它总比少分配更经济。单地预留继承当前教师的候选策略，不是官方禁止同地多个操作。这里没有增加完整官方动作类别，也不宣称覆盖运输、商店、扩地或养殖决策。logit 不是预期现金收益，当前匹配也不是整回合最优联合动作。

种子、肥料、仓容、运输、作物选择、市场和雇工仍由原控制器处理；它会在新轨迹上重新规划，后续经营行动可能随状态改变。不会新增距离权重、温度、销售规则或种植批次。原网络首选与解码实际选择分别留证，不把候选 ID 变化等同于完整请求或官方状态变化。

独立子代理读取全部十四份原件，核对登记链接、十份源码、安装中的规则／core／spec 哈希、初态、四段连续状态和执行事件，没有重跑引擎。真实进程退出码零由执行者观察；原件没有进程退出收据或内存采样序列。回调输入仅保存摘要，不能说独立复核已从原件逐字段证明输入私有隔离。隔离路径有静态检查。

微场景验证的是 `TaskAgent + decoder` 和合成分数，没有真实权重前向、完整比赛或未来收益。合成包装回归和额外的真实 gzip 内存编解码验证覆盖计费与记录，不替代本次完整权重对局。执行原件和十四文件清单留本机，不重跑已关闭的微场景入口。

## 技术验收、预算和停止条件

四场均须官方 720 状态、719 次动作、双方 DONE、无 Agent 错误。复用原 Worker、同次官方主复演、执行追踪、现金消费者和收据验收；在同一次复演中复用既有仓库顺序增强，核对双方 720 帧仓库次序，不额外启动第二次官方复演。现场与审计使用同一候选和同一冻结权重；审计重新计算请求和完整 trace，确认预算及解码记录。

每次启动前至少三次连续 6 GiB 可用内存采样，间隔十秒、最多等待三百秒；运行底线 4 GiB。单受管 Job 的 RSS／commit 上限 2／3 GiB、九百秒、清理十秒。整个四局与结果比较共两小时，磁盘底线 4 GiB，阶段总产物上限 1 GiB、私有汇总 16 MiB，每局预留 160 MiB；原 Worker 的受管 Python 写预算仍为每局 128 MiB。离散监控不是连续保证，Python 写预算不是操作系统硬配额。

复用的 LocalDriver 可能记录通用二十四局容量；实际登记、固定计划和运行循环仅允许这四场。任何身份、执行、复演、资源、存储或清理检查失败，停止并保留证据，不重试、不补抽，不对部分通过场次输出总体收益。

比赛退出与完整结果验收分开记录：四局完成后仍须完成逐例 trace 与旧对照比较，最终证书成功才可称本轮技术通过。比较一次只解码一份受限 Replay，生成逐帧摘要后释放，再处理另一份；这不是压缩 JSON 全程流式解析。完整请求、去除动作和日志后的官方状态、背包及显式仓库顺序分别处理，不能把动作文本差异当成物理状态差异。

## 预先固定的统计与开发门

保留每例完整自身净收益、对手净收益、终局双方现金差、得分与配对增量；净收益为终局现金减初始现金。报告案例等权和两个实际“种子—对手组合”等权均值、正／零／负计数，两个组合分别列示。对手和 seed 在本设计中混杂，不能解释成独立对手效应；双席也不是两个独立 seed。同一初始 seed 不保证策略分叉后随机数调用路径相同，终局差包含后续经营、对手反应、共享市场与可能的随机流变化，不做独立因果百分比分解。不计算显著性，不自动晋级，不修改默认 Bot。

开发信号同时要求：至少一次网络首选与解码选择不同；至少一场对比旧控制局出现完整请求和物理状态差异；整体平均自身净收益增量大于零；整体现金差和得分不退步；F01／market、F02／round2 各组合的自身收益、现金差和得分均不退步。源代码中的 `contract.project` 固定这一判断，不因结果改变口径。通过仅表示值得后续更广评估，不表示独立泛化或可推广收益。

没有执行差异或开发门失败时，封存候选和负结果并停止该分支，不追加参数、训练步数、seed 或完整比赛。本轮不训练、不做 BC／DAgger／PPO、不使用 GPU、不进行线上提交。保留旧策略、权重、证书、原哈希与历史结论；原始 Replay、逐步私有状态、日志和本机路径不上传。

在本仓库根目录，使用已有游戏虚拟环境的 Python。以下是本次唯一新阶段的执行顺序，不是可反复生成同一面板的通用命令：

```powershell
$GamePython = (Resolve-Path ../../kaggriculture/.venv/Scripts/python.exe).Path
& $GamePython -I -B kaggriculture/learning/task_joint_decoder_v1/runner.py --prepare
# 完成独立检查、隐私检查并本地提交登记后，记录该提交：
$RegistrationCommit = git rev-parse HEAD
& $GamePython -I -B kaggriculture/learning/task_joint_decoder_v1/runner.py --preflight --registration-commit $RegistrationCommit
& $GamePython -I -B kaggriculture/learning/task_joint_decoder_v1/runner.py --run --registration-commit $RegistrationCommit
& $GamePython -I -B kaggriculture/learning/task_joint_decoder_v1/runner.py --results --registration-commit $RegistrationCommit
```

每步必须实际退出零才进入下一步。`--prepare` 不启动模型推理或比赛；四局运行完成只产生待比较状态。第一次 `--results` 必须在同一次两小时总预算内完成，失败后不重试。已生成最终证书时，该入口只读验封，不再重新解码完整轨迹。运行和验封均要求登记提交对应的干净工作区；后续结果提交的 HEAD 不能冒称该冻结运行版本。内部 `--game` 仅供受管子进程使用，不能单独手动补跑。不要重跑已经关闭的微场景入口。
