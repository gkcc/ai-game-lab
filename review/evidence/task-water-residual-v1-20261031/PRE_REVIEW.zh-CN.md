# 浇水残差 GPU 探针：执行前复核

两名独立子代理复核模型组件和运行链。先前在纯合成输入中发现组内相同特征的舍入伪梯度，训练改为减去组内首候选并以 JAX CPU 复核零梯度；开发 NLL 大数消减及已知失败被误标 unknown 的反例也已修复。训练使用 float32 基线／中心化规约，部署使用 float64 基线与直接点积；本轮登记要求检查实际入选组的精度首选变化，以及开发候选的 GPU／CPU 相对分数和首位最大值。

入口审查用反例发现：监管进程退出成功却缺失模型可被误报成功、写收据失败可能遗漏等待、空 GPU 比较可能被判通过。现将产物验证和 Windows 侧开发重算纳入完成条件，在异常中仍等待拥有的子进程；比较人口由已认证开发组重算，空比较拒绝。Windows 与 Linux 的单次尝试标记、父进程身份、pidfd 会话清理及内存／磁盘采样按登记执行。清理无法确认时不得声称成功，也不通过终止整个 WSL 补救。

在 Windows 和 WSL 的隔离解释器中已完成不读取真实数据的模块导入探针。相关合成回归涵盖 59／62 组的端到端假后端、float32 全候选首选变化、缺产物和空比较；它们不能证明真实 GPU 更新、真实数据标签质量或 WSL 进程清理。64 步 CPU JAX 测试使用合成输入，不能替代本轮真实设备验收。注册、源码和私有来源身份须在真实模型前向前固定并推送。

同一输入下只保护动作类别：改变浇水候选仍可能改变后续游戏状态。旧 `TaskNetwork.last` 遥测接口与新选择器不兼容，未经适配不能直接接旧完整比赛消费者；开发筛查不是独立竞技评估。数据已消费，未对新种子、未使用留出面板或正式比赛做出结论。
