# 历史多机制教师来源：只读兼容性检查

独立子代理只读核验两份明确标为已消费训练输入的旧档案，与其公开登记的档案身份承诺一致；仅解码档案中的 seed 元数据并与本次已完成来源角色比较，没有解码旧候选特征或标签、调用模型、训练或运行比赛。旧来源四个已消费种子簇与本次两个训练角色及两个开发角色的 seed 值均不相交；不相交并不排除相似或相同的数值状态，也不证明独立泛化。

两份旧档案的 schema 原字节一致；主要核查者读取认证基线的元数据，确认其 275 个共享及 98 个候选特征的有序语义 schema 与旧来源一致。第二名复核者核对了两份旧 schema 与登记的一致性，但没有独立读取基线元数据。根据历史公开登记，这两份旧训练输入合计 5,104 组、322,151 个候选，教师目标包含浇水 3,516、施肥 820、挖地 62、收获 385、种植 321。这里的操作数量沿用历史登记，本次没有独立解码并重算标签，也不能把同一场或同一种子的组当独立比赛。

为后续把多机制旧示范与新的多教师浇水选择结合，来源和 schema 有初步兼容证据；合并前仍须分别绑定训练与开发身份，核查跨来源数值重复、不同教师的冲突标签以及原模型归一化。粗略估计，两档压缩文件约百余 MiB；若把共享特征复制给全部候选并进行 float64 标准化，会产生数百 MiB 至近 1 GiB 的额外中间数组，因此应按组或小批流式处理。这是根据数组形状的估算，不是实测峰值，也不能保证当前内存可以运行训练。

读取范围有一处例外：子代理查看一份公开历史说明时，意外看到两个当时预留的 seed 字面值；尚未核实它们后来是否已使用。这两个值没有用于本次身份比较、参数、训练或比赛，也没有写入本轮结果；为避免把已暴露的值当作新鲜测试，后续独立测试必须排除它们。另一名复核者的两次工具输出意外回显了旧的、已消费训练 seed；这些输出没有写入本轮 Git 成果。一次关键词检索覆盖公开仓库的跟踪文件，随后文件枚举对照未发现其范围包含私有未跟踪数据。结果只支持下一阶段设计，不证明新模型、比赛收益或 GPU 加速。
