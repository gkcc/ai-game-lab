## 接线必须保留两个学生

复用 `task_harvest_choice_v1/adapter.py` 的候选扩展与槽消费，以及 `task_choice_v1/agent.py` 的模型构造路径。当前微场景适配器构造器固定 `crop_mode='teacher'`；直接套用它会把旧双模型 baseline 的选种学生换成教师，造成第二个实验变量。因此新薄适配器必须保留原任务检查点和同一个选种检查点，默认 Bot 和原有构造器不改。

`task_teacher_fresh_panel_v1/sources.py:load()` 已定义完成的 32 场来源认证及模型身份解析。任务模型使用对应 manifest 的 `panel.models[0]`，选种使用 `panel.crop`；路径和 SHA 从既有私有身份绑定读取并核对，不能猜 NPZ 文件名。该 loader 的完整来源认证与子进程已绑定后的轻量模式用途不同，不能把后者当成绕过父进程认证的开关。本轮规划没有读取这些旧私有文件或权重；新轮输入范围和认证成本须另行登记。不调用会重读种子排除库存的旧 prepare 入口。

保持 275 个共享特征、98 维原候选和前缀顺序。TaskNetwork 可以计算相同 schema 的新候选，但这不证明新候选的决策分布已经被训练覆盖，也不意味着 logit 是现金价值。不要复活 joint matching、加入收获偏置或强迫模型选择新增动作。

## 有界实验与停止条件

沿 `task_harvest_struct_compat_v1/contract.py:sources()` 使用原四个消费来源：C01/S02/market/席0、C01/S03/round2/席1、C02/S02/market/席1、C02/S03/round2/席0。身份、原点或旧对照缺失就关闭，不换种子／案例。

先在四个原点各比较原双模型与禁用扩展适配器的完整请求、资源预留和选种记录；另各做一次原池／扩展池评分对照。预先固定浮点容差，原候选 logits 须有限且在容差内一致，原候选 argmax 完全一致，精确平分仍由原前缀获胜。这只验证四个同观测兼容点，不等于复现旧 baseline 的全部 719 步。

前置通过后，仅运行四场始终启用扩展、直接服从真实权重 argmax 的完整对局，各做一次现有官方主复演及 Actor 重建。预算必须把复演和所有前置推理算入：

| 操作 | 硬上限 |
| --- | ---: |
| 新完整比赛／官方主复演 | 4／4 |
| 比赛动作／复演动作 | 2,876／2,876，共 5,752 |
| 环境构造／初始化 | 8／12 |
| 完整轨迹本方 Actor 调用 | 现场 2,876＋重建 2,876 |
| 同观测完整控制器检查／单独评分 | 8／8，另外计数 |
| 任务前向／选种前向 | 32,264／64,512 |
| 神经输入行 | 1,345,536 |
| 训练更新／GPU／新种子／重试 | 均为 0 |

前向预算来自八条现场／重建轨迹各 4,000 任务、8,000 选种、160,000 输入行，加八次控制器检查各最多 32／64／4,096，以及八次单独评分各最多 4,096 行。官方正常 `make→run` 会在构造后再 reset；主复演只 make 后 step，所以预期初始化为比赛 8＋复演 4，不能只报八次构造。实际入口必须计数验证这些预算；如果实现路径不同，在读取新结果前修正登记，不能事后解释超限。

沿已有串行资源边界：启动和间隔至少 6 GiB 可用内存、运行至少 4 GiB，Job RSS 最多 2 GiB／commit 最多 3 GiB，每 Job 最多 900 秒、总运行最多两小时、新产物最多 1 GiB、磁盘可用至少 4 GiB。它们是硬上限，不是吞吐预测。复用现有 Worker、Windows Job、流式证据及复演，不再搭建新平台。

四场均应达到 720 状态、719 动作、双方 DONE，零 fallback 和模型错误，源码身份、完整请求、顺序和主复演一致。记录新增候选出现次数、分数与被选次数，并关联实际请求、官方 HARVEST 执行和整局结算。如果权重从不选择新增项，报告“无新增动作控制证据”；不能临时补强制选择、换模型、加样本或重训。
