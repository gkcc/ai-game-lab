# 新面板动态种子重扫：准备阶段

上一次面板未完成，四个种子角色均已消耗。选种前快照若漏掉某条历史记录，而该记录随后被删除，开赛前重扫也无法补回。因此，新组件分别提供选种前的增强快照和登记后的动态重扫；本阶段不生成新种子、不运行比赛、不训练，也不读取失败面板收益。

`preselection_inventory(new_out)` 在新阶段目录创建前验证旧登记和失败证书，合并原排除集与增强历史扫描，绑定干净的父提交并检查扫描前后的元数据身份。它识别约定的 seed 字段、别名和索引映射、整数型浮点及数字文本，扫描项目内白名单登记及 `job-inputs`，包括符合白名单的私有子目录和 Git 忽略文件；不读取 `games`、`traces`、`results` 等结果目录。旧清单可能造成保守的额外排除，不能推断这些值都是真实历史种子。任何输出或日志都不得包含私有种子、盐或清单内容。

`rescan_registered(stage, prereg_commit)` 校验干净 HEAD、父提交、阶段目录、四份既有登记证据及附加的 `safety-registration.json`，绑定私有种子承诺、冻结历史快照和本地归属标记。重扫时合并旧失败批次四个种子、冻结快照和当前可识别历史；本阶段公开证据仅允许五个已认证文件，本地对局输入需匹配固定计划和来源哈希。它应在首场前、每场启动前和最终评分前调用；新增冲突、异常元数据或证据变化时停止，不补场或换种。

这些组件不能单独授权比赛。正式协调器仍须确保快照在选种前生成、目录排他创建及单次启动，核对标准策略包装器而不只相信输入自填哈希，验证完整官方规则、冻结源码和资源预算，并保证失败不重试、跨进程等待预算和结果发布流程。标记与哈希证明约定下的身份，不是第三方时间戳；路径检查也不能防止同用户在检查与使用间替换文件。扫描只覆盖约定元数据，外部、未纳入快照且已删除、结果目录或不符合约定格式的历史仍无法保证。

## 验证结果

资源等待、原种子组件和新重扫组件合计 58 项合成回归：57 项通过，1 项文件符号链接用例因权限不足跳过；Windows 目录联接用例通过。独立子代理复核了别名、映射、浮点、Git 忽略文件及新增历史冲突，并在合成 Git 仓库核验父子提交与工作区状态；自有临时目录均已清理。

主代理只读检查真实历史快照，确认失败批次四个种子全部被排除，未输出值，也未创建新阶段。该只读检查及公开投影不能单独证明私有文件内容或未来比赛效果；本阶段没有新比赛、训练或模型晋级。
