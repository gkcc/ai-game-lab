# 有限任务选择 BC：新版本复做

本阶段在已经消费的训练样本上，以相同随机种子和优化器配置进行一次新的、受控的训练执行。旧阶段的唯一尝试仍记为失败，旧检查点不封存、不覆盖，也不把本次运行当作退还旧次数。前面的数值对照表明，在固定 16 组上请求 JAX `highest` 后 GPU／CPU 分数差异减小，但不能唯一确定旧异常的原因。

唯一策略改动是训练后 GPU／CPU 推理一致性检查请求 `highest`；训练步骤仍用原有默认精度。新增分阶段进度与失败收据。成功必须同时具备设备身份匹配、128 次同步更新、非零梯度、权重变化、16 组数值对照和 Windows／WSL 自有进程清理，之后才能封存最终检查点。阶段失败不重试。

预登记两个未在可检索历史中出现的新测试种子，对两个冻结对手交换双方位置，共收集 8 场完整官方比赛；总预算还包含逐场主要复演、独立标签复演和一场独立抽样复演。旧阶段预留的两个种子不复用。种子搜索范围与无法检查已删除或外部历史的限制写在登记中。

这些比赛使用固定任务教师与冻结选种模型生成决策示范，新训练模型不参与比赛。评估比较冻结候选集合内的离线预测与训练集频率基线，按既定门槛分别报告操作类别、种子和多候选情形；两个种子只能提供探索性信号，不能证明实战胜率提升或统计显著性，也不自动晋级教师。真实模型控制的官方比赛需要另立实验。

公开登记为本地提交，不是第三方时间戳。原始回放、动作追踪、标签、特征、模型权重、个人设备配置与日志仅留本地；旧策略、默认 Bot 和官方规则均保持不变。

## 实际结果

事前本地提交 `bb057d69775d0f7b048b6a947ed8fe7b0eca04cb`。一次 GPU 训练完成 128 次同步更新，128 次梯度非零，最终权重相对初始化变化；16 组、1741 个候选的 GPU／CPU 对照通过，最大绝对差约 0.00000130，Windows 与 WSL 自有进程清理收据通过。训练过程本身没有改变默认矩阵乘法精度；只在训练后的前向对照请求 `highest`，没有测量硬件实际运算精度或 GPU 加速比。

新检查点与旧阶段未封存检查点的字节 SHA256 完全相同。新阶段有自己的训练与清理证据，但旧阶段仍是失败，不以本次结果追认旧阶段。训练输入仍是历史已消费数据，包含原 baseline、candidate 和固定 task teacher 产生的选择，不能称作纯教师示范。

两个新种子对两个对手交换席位的 8 场比赛全部结束，均为 720 状态、719 次动作、双方 DONE、零 Agent 错误，主复演通过；另外 8 场标签复演和 1 场独立抽样复演完成，总计 17,975 次官方状态转移。生成 8,639 个任务片段，其中 6,758 个观察到对应即时效果、1,881 个未知。未知不视为失败。额外复演按事前固定身份选取 20 段，20／20 一致；其中 18 段是 WATER、1 段 HARVEST、1 段 PLANT，没有覆盖 DIG 或 FERTILIZE。复演共用官方引擎和输入校验，独立实现的是任务片段与效果判定。

8 场用于采集教师示范，新任务模型没有控制其中任何比赛，因此尚未验收其在官方对局中的影响或竞技能力。独立审查重新计算了公开聚合门槛并核对身份与计数，未读取测试数组、逐条分数或权重，也没有独立重算每条预测。原始回放和追踪、逐条标签、训练与测试数组、权重、设备配置和日志仍只留本地。
