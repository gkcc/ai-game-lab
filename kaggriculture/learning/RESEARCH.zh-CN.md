# Kaggriculture 自动学习：首轮路线与源码阅读

2026-10-18。先结束手写策略迭代，把官方规则、控制器及对手固定；此后由实验程序生成候选、收集真实对局、选择与测试。第一轮不是完整 PPO 平台。

## 已冻结的手写能力

原第一版 `bots/heuristic_v1.py` 与默认 `main.py` 字节相同，SHA256 为 `74943a2e174c1fe1f9ed2e434d8aef5f13aeddc5575d06c0949ebf6bde818459`。原六种子池中，对第二版10胜2负、对按需购种版12胜0负；只会初始25格的作物经营，没有动物/买地，不能据此推断公开榜水平。

市场版 `bots/heuristic_v1_market.py` 单独冻结，对三版36场18胜18负；对原第一版8胜4负、第二版0胜12负、按需购种版10胜2负。甜瓜36场均未触底，但保价也可能让对手受益，故不替换默认。收获产品全部实际售出、双方农活审计通过，保持官方720状态/719动作转移。

首轮自动搜索以原第一版作固定控制器，只暴露4个作物评分倍率（小麦固定1），不继续为每个输局人工添加规则。市场版保留为下一阶段额外对手。

## 两个公开实现：阅读了什么

两个仓库仅克隆为只读研究材料，未安装、未运行其训练脚本、未加载检查点、未编译加速器。下述大型模型的实力与性能属于作者描述，不是本机验证结果。

### CarsonBurke

Commit `ab1e8819d7bab850deb594ff17686dbc81598eca`，本地 `research/CarsonBurke/`。

依据：[技术说明](https://github.com/CarsonBurke/kaggriculture/blob/ab1e8819d7bab850deb594ff17686dbc81598eca/docs/solution.md)、`src/kaggriculture/tokens.py`、`actions.py`、`league.py`、`rollout.py`、`rust/kagg_env/`。

| 方面 | 源码与文档中的设计 | 对本项目的意义 |
|---|---|---|
| 编码 | 200农地token＋20经济token；16己方单位、10市场决策槽。公开双方农地＋己方私有资源；额外对手私有信息仅供集中式critic | Actor禁止读取训练时才能拿到的对手私有字段 |
| 动作 | 单位68种原语；市场22种订单类型，再选数量1–100或ALL | 把巨大的联合动作拆成有顺序的条件决策 |
| 屏蔽 | 顺序更新单位种子/地块占用和市场资源账本；数量与ALL概率合并一致 | 训练与部署的合法支持集、log-prob必须一致；合法屏蔽可能比游戏容忍的动作更窄 |
| 训练 | BC初始化，critic预热，再PPO；约947k参数家族，W/D/L critic，训练辅助表征目标 | 先把监督学习和价值拟合跑通，避免从纯随机动作长季节探索 |
| 批量仿真 | Rust＋PyO3，游戏之间Rayon并行，GPU负责网络 | GPU不是Python解释器的替代品 |
| 对手池 | 不可变历史快照、难度后验、陈旧对手探测、固定参考和独立外部面板 | 单一starter或只打最新自己会产生虚假的进步 |
| 评估 | 明确解码模式，留出种子/参考对手，最终回官方引擎 | 训练胜率和critic拟合度不作为实力验收 |

|---|---|---|
| 编码 | 124列类型特征，最多264token；公开信息推断的对手库存记忆，不是偷窥私有仓库 | 可逐步增加记忆，但必须重置每场状态，并标明估计不确定性 |
| 网络/动作 | JAX、12层约10.23M参数Transformer；单位500 logits，市场每槽1903个解码选择 | 本轮不直接复制这种规模，也不把小MLP速度外推到大网络 |
| 合法性 | A：置信度排序修补、仓容保护、末日C++搜索；B：顺序条件mask，训练推理同支持集 | 学习宏观选择，规则兜住资源和末日清算，是可行的过渡路径 |
| 训练 | BC→critic拟合→自博弈PPO，可再BC；规则强制的动作不参与策略梯度 | 修补动作必须从学习目标中正确剥离，不能拿改后的动作冒充采样动作 |
| 批量/对手 | RustBatchEnv＋Rayon；公开示例64局、双席位，自博弈＋固定KL教师；保留快照与last-best原语 | 示例不等于完整动态联赛，更不等于本机已有完整训练链 |
| 评估 | 官方环境、每种子交换双方、独立进程；数据按episode留出 | 不能把同局相邻帧随机切开后声称泛化 |

## 方法选择

| 路线 | 优点 | 首轮代价/风险 | GPU用途与本轮结论 |
|---|---|---|---|
| Optuna/TPE | 少量真实比赛即可调混合/连续参数，SQLite保存每次试验 | 只能改固定控制器的参数，不能创造新动作；容易过拟合小种子池 | 采样器和Python仿真是CPU；本轮主实验采用 |
| CMA-ES | 连续参数间有耦合时可自适应协方差，无需梯度 | 需要多个种群世代，离散开关/截断可能损失效率；预算很小时难判断 | 同样不能把官方Python环境自动变成GPU仿真；后续可作优化器对照 |
| 行为克隆 | 监督信号密集，GPU有效，可学习作物/交易/任务选择 | 学到教师偏差，运行时状态分布漂移；分类准确率不等于赢比赛 | 本轮另做真实样本GPU探针，不将其权重接入正式Bot |
| PPO＋自博弈 | 能优化长期胜负、探索超出教师的策略 | 719转移的延迟奖励、巨大组合动作、价值预热、对手池坍缩、环境吞吐 | GPU负责网络批推理和梯度更新；目前不直接开始长训练 |
| 规则控制器＋学习模块 | 保留合法动作、路径、资源与清算保障，先学少量宏观决策 | 控制器仍限制上限，必须定义清晰接口与回归检查 | 下一阶段最值得验证：小网络选择作物/销售宏动作，先BC再小PPO |

[Optuna TPE说明](https://optuna.readthedocs.io/en/stable/reference/samplers/generated/optuna.samplers.TPESampler.html)；[CMA-ES作者资料](https://cma-es.github.io/)。

## 官方仿真性能与CUDA GPU

完整实测见首轮自动实验的 `benchmark.json` 和 `benchmark/profile/profile-*.txt`。第二次测量：单个worker顺序运行4场，包含双方Bot调用，约 **0.438场/s、315次官方转移/s**；连同双方审计与gzip回放，约 **0.305场/s**。冷导入单列，渲染不在该吞吐内。

每场运行约2.28秒，其中双方Bot约0.26秒、环境与框架约2.02秒。带cProfile的另一次比赛显示 `copy.deepcopy`、`structify` 是主要热点；其8秒耗时含剖析开销，不混入吞吐分母。不能把这些时间简单加成互斥的函数耗时。正式搜索使用两个本地CPU worker，未搭集群。

因此CUDA GPU不能加速当前Python字典、深拷贝、规则循环。网络批推理、BC和PPO梯度可放GPU，但这不等于整条训练链已有GPU加速。单worker按315转移/s推算1亿转移约88小时，仅是粗略模拟时间估计，不含网络/审计/I/O，也不是实际跑过的长训练。

GPU探针的匿名汇总保存于 `review/evidence/gpu-bc-probe.json`：从冻结第一版的22场真实胜局提取1680个成功种植样本，按整种子分成824训练、856验证样本；43维输入、128隐藏单元、5作物分类器。CPU和CUDA GPU各实际执行512次梯度更新、batch256；权重改变、损失下降，训练/验证准确率分别约93.9%/88.8%。

该探针计时包含所有权重和loss的阻塞host拷贝；GPU排除编译后约0.0187秒、CPU约0.0687秒，微型任务约3.68倍。GPU编译＋预热约1.71秒，明显超过这次小训练本身。它只证明本机能训练这个小网络，不能证明比赛Bot增强，也不能推断大Transformer/PPO的倍率。其模型没有进入Optuna候选或独立比赛评估。

探针使用WSL JAX运行时；机器配置不公开。后续正式神经训练应使用独立锁定环境。

## 非官方加速器的使用门槛

两个公开实现都以 `kaggle-environments==1.32.7` 为规则基准；本机已验收的是1.33.0、官方Commit `f994f2050d58d84f649329c1e35ce09ada7007c5`。作者的parity声明不替代对本机版本的验收。本轮完全不用Rust/C++模拟器训练。

下一阶段采用前必须至少做到：

1. 同初始状态、同参数、同种子、同联合动作，每一步比较双方公开与私有状态；完整719次转移，末局状态/奖励/胜负相同。
2. 专门比较逐单位交错SELL、订单顺序、价格舍入、报价1时卖货不再增加市场库存、买种与种植的先后。
3. 比较雇工斐波那契、同地块/种子竞争、DROP及夜间溢出丢弃、库存插入顺序、末日没有自动送仓的行为。
4. 比较杂草和商店共用RNG、商店有放回抽样、town消费时点；不得只比最终余额。
5. 随机合法动作、针对性边界用例、冻结真实Bot轨迹均通过；再用留出种子交换双方回官方引擎复核。失败就停用加速器，不在偏差规则上长期训练。

## 首轮实验约束与下一步

Optuna仅使用2个训练种子和第一版/第二版对手；最终唯一候选选定后，才打开预先写入配置的12个新种子，分别与3个冻结对手交换双方。原版也跑同样面板，按整种子聚类bootstrap，避免把双席位/多对手虚增为独立样本。

提升门槛预先规定为“净收益差和比赛得分差的95%区间下界均大于0”。即使训练分数上涨，也可能不通过。测试结果不得反馈调参或决定再挑一个候选；否则需要新的未见测试集。

本轮最终通过该面板门槛，平均配对净收益增加752.04（约1.93%）。但最佳候选是编号2，来自4次启动试验以内；后续4次TPE建议没有超过它。因此本轮证明自动生成、对局、选择和独立验收闭环有效，不能证明TPE优于随机搜索。

这轮结束后停止人工策略增补。下一步优先把“小网络宏观决策＋固定合法控制器”接入完整官方比赛，验证BC是否保持教师能力；同时对选定加速器做版本一致性审计。两者通过后再做小规模PPO自博弈，暂不直接开启大规模完整RL。
