# 两臂任务模型：历史开发比赛入口候选

本目录提供历史开发比赛入口候选：固定 2 个已消费历史角色 `S02`／`S03`、`market`／`round2`、双方席位及 `baseline`／`control`／`auxiliary` 三个任务头，共 24 场。是否已经登记或完成比赛，须看相应登记和结果记录。角色别名不包含真实种子；原始种子与私有模型路径、模型摘要、比赛输入、回放和追踪均只能留在本机。这里的历史开发面板不是独立测试，也不会改变上轮开发筛查失败的结论。

`panel.Panel.from_private_contract` 只检查传入值的结构、互异性和角色关联，并将其复制为不可变快照；它**不认证**真实种子是否属于所称历史角色，也不认证模型、作物头、对手或来源。调用方必须在事前登记和启动之前，依据既有历史材料独立绑定这些身份，不能以读取后现场计算的哈希冒充历史证明。`Panel.plans()` 返回含真实种子的私有内存对象，不得打印或发布。`worker_config()` 不包含 `test_seeds`；本入口不调用旧 `prepare`、`seed_inventory` 或正式留出测试协调器。

三个任务头各绑定一份路径和预期 SHA，所有计划共享一份作物模型路径与预期 SHA。`worker.make_wrapper` 与 `worker.run_job` 接受经调用方认证的单次有界 anchor Worker 源码字节及其事前固定摘要；先在内存中核对 SHA，再编译**同一份字节**到独立模块对象，绑定仅作用于该对象，不修改已导入的旧 Worker。它复用旧 Worker 的官方比赛、`BoundedAgent`、逐步请求重构和官方有序状态复演；本模块代码本身不能证明比赛或复演通过。它也不验证其余被导入模块和第三方依赖的来源，须由正式启动器认证。

隔离副本的重构 trace 比较先沿用旧 `stable` 递归过滤 `inference_seconds`，再使用现有 `_typed` 比较其余字典顺序及数值类型；因此 `1` 与 `1.0`、`+0.0` 与 `-0.0` 均不同。非有限值或非字符串字典键会拒绝。该更严格口径只适用于新入口，可能保守拒绝此前普通字典比较通过的记录，不修改历史证书；已对合成记录验证，不能代替全部真实轨迹的验收。

计划只接受固定的 24 个 `dev` 组合；私有 job 必须匹配种子角色、双方席位、对手、三任务头和各自预期摘要。源码、私有登记和模型认证由调用方的 `check` 完成；本模块只要求该回调返回严格的 `True` 并在关键位置再次调用，回调自报不构成独立来源证明。job 文件读取限定大小、拒绝重复键和非有限数字。路径只允许游戏根下的 `artifacts` 相对模型路径，实际文件、目录链接和检查之间的并发替换仍须由调用方按正式合同处理。

单场候选接入 `GameConsumer`：在原 audit 的唯一 `reexecute` 调用中，将相同事件先交给原 sink，再交给消费者；同场已保存 trace 按序消费 719 行。trace 在同一个打开的文件句柄上做前后 SHA 校验，压缩文件最多 128 MiB、单行解压最多 8 MiB、总解压最多 512 MiB；哈希和普通文件句柄不是并发写锁。原 audit 完成后，消费者核对执行标签计数、双方结算与现金变动。随后才在独立 8 MiB 写预算内排他保存本地指标、逐选择事件及带 SHA 的本地收据并读回。这个预算与旧 Worker 的单场 storage 账分开，不证明整个进程峰值内存。

调用方必须使用已受管的专用子进程并在调用前完成身份验证；模块只检查调用发生于主 Python 线程且没有其他活跃 Python 线程，不能证明进程归属、原生线程隔离或系统级锁。运行时抑制 Python 标准输出及原生 fd 1／2，失败只向调用者抛出固定错误文本；本机私有日志和比赛结果本身仍可能包含真实种子、路径及私有状态。输出边界要求 fd 1／2 可复制：Windows 无控制台的受管启动器若未显式提供有效句柄，可能在比赛前失败；必须用真实启动路径另行验证，不能把合成子进程测试当作该验收。

旧 Worker 的单场 storage 收据原本写“由父进程有界日志承接原生输出”；此候选只在隔离副本写入当前场该收据时，将该字段改成 Python 与标准 fd 1／2 导向 NUL、其他原生句柄未独立验证的实际口径。旧 Worker 文件和其他历史收据不变。

同级 `task_pair_dev_campaign_v1` 实现了外层准备、单场监督、共同前缀比较及汇总的候选入口；这些代码是否已经完成独立审查、登记和真实验收，须以对应登记与结果文件为准，不能从本模块推断。旧 Worker 自带的单场写入及模型调用预算不等于整体资源监管。若新指标保存失败，旧 Worker 可能已写出自己的完成标记；外层必须同时核验新指标与收据、进程成功退出和监管清理，不能凭旧标记接纳。`run_job` 正常返回也不代替上述外层核验。不得在完成独立审查、登记及这些必要条件之前运行真实比赛。

合成回归不读取真实种子、模型、回放或训练数据，不使用 GPU、不运行游戏、不创建临时目录：

```text
python -B -m unittest learning.task_pair_dev_games_v1.test_panel learning.task_pair_dev_games_v1.test_worker learning.task_pair_dev_games_v1.test_capture
```

测试以假 Worker 和合成事件验证角色、身份、隔离绑定、一次复演的双 sink、现金闭合及失败传播；用内存文件替身检查有界 trace 和指标读写。另用真实短子进程和合成输出验证标准输出及 fd 屏蔽。假 Worker 不能证明真实比赛链路、正式来源认证或 Windows 无控制台 Job 的句柄行为。
