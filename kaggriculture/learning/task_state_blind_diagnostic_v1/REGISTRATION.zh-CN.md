# 状态残差在已消费轨迹上的盲选开发诊断

本方案仅检查冻结残差在更多历史学生状态中是否改变任务候选首选，以及与当前条件教师目标的一致情况。不训练、不更新模型、不运行新比赛、不做 GPU 运算、不进入 PPO、不修改默认 Bot。历史状态残差事前筛查为 **failed**，本阶段不能改判其结果、自动晋级或启动对局。

## 来源与盲选

来源为已经完成并消费的 Anchor baseline：固定 A05、A06，分别在 market、round2 对手下交换学生双方席位，共八条完整历史轨迹。每条轨迹验逐场收据、模型、官方规则和 replay 摘要；同一文件描述符上完整扫描 719 行并前后校验 trace 摘要。历史官方复演收据记录的 719 次转移与本阶段的读取是不同证据；本阶段不重新执行官方转移。已消费的角色映射仅在本机内存和私有绑定中处理，不打开未运行种子清单。

每场按 0–119、120–239、240–359、360–479、480–599、600–718 分六窗。先仅在有任务回调的 step 之间用角色、对手、席位和 step 的固定域哈希排序，每窗最多选四个不同 step；随后在每个入选 step 内用独立哈希域选择一个 ordinal。两步均不以教师标签、学生选择、动作、残差结果或收益筛选；空窗不补位。最多八场、192 组，每回调最多 256 个候选、每回合最多 32 个任务回调；超限停止，不截断或挑替补。719 行语义扫描器会核验标签和历史记录的合法结构，但不参与盲选排序。

逐个已选回调严格比较其单方 observation 和 configuration 与同一步官方 replay 经 `observation`、`observe` 得到的视图，保留键顺序、列表顺序、标量类型和浮点位表示；另核对自身背包和仓库顺序。提取器核验单方视图、schema 和部分候选身份/几何/动作字段，但不从观察重新计算每一维数值特征。缺失、超限、视图不符或基线首选不能逐组复现历史 `chosen` 均停止。单候选、教师等于学生及重复样本保留在主统计；不根据效果过滤。单方教师目标、标签和匿名角色均不输入模型。

## 测量与边界

使用事前冻结的基线任务网络和状态残差 NumPy 部署公式；冻结模型在此之前的筛查未通过。统计总量、匿名角色、对手、历史学生席位、时间窗和目标动作的覆盖、首选变化、条件教师目标匹配、成对改正/回退四格和条件 NLL。另在本机保存八场各自的选中组数及六窗覆盖，空场记零、不补样，不保存逐场效果指标；逐场覆盖与各分区总数交叉核对。单候选参与总体，不对它计算 margin。每组的基线网络只评分一次；同组为角色、对手、席位和时间窗四个分区分别调用残差评估器，每次评估器内部重新计算残差并核对选择，不能称每组残差只前向一次。

仅统计本次入选样本内完整有序候选组的 raw32 和标准化 float32 精确重复，均不剔除；两个表示都把正零和负零规范为同一数值并保持候选顺序，因此不声称原始字节完全相同。不扫描与全部历史训练档案的重合，也不声称不存在精确或近似重合。结果依赖历史基线访问到的状态，只有两个已消费种子簇；每 step 至多一个回调，比例不是全部游戏动作的自然频率，不能称独立泛化、显著性、实际动作执行、胜率或收益。条件教师目标不保证在官方引擎中执行或更有收益。

## 准备、运行与发布

`prepare` 仅在指定干净父提交和可用内存至少 5 GiB 时认证已完成来源、失败的历史筛查、模型/schema 身份并建立带盐私有绑定和公开登记；不读取比赛、不模型前向。将源码和登记提交并推送，复审通过后才可 `run`，限定一次命名 Windows Job；运行期间采样可用内存不得低于 4 GiB，Job RSS/commit 上限为 2/3 GiB，时限 900 秒，磁盘至少 4 GiB 加输出预留。采样并非硬实时保证。失败停止且不自动重试；回放逐场释放，仅匿名汇总落入新私有结果目录。

历史逐场 row/audit/complete/storage 和 wrapper 依旧由既有证书链认证，原 job-input/result 是语义交叉核对，不声称两者被单独哈希绑定。完成不等于晋级；发布任何结果前另做项目隐私检查，小分组仅保存在本机，种子、私人路径、原始观察、特征、权重、回放和逐组数据不上传。
