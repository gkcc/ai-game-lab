# WSL 双臂训练入口候选

本目录是一次有界实验的**子进程入口候选**，当前没有正式登记，也没有通过真实数据、模型或 GPU 的端到端验收。入口缺少固定登记时会在读取本机数据、私有合同或启动 GPU 之前失败；现有 WSL 导入守卫也尚未完整覆盖本入口，须先扩展并独立复审。不要直接把本文件当作已批准的训练启动命令。

在正式运行前，调用方需要先固定并提交公开登记，覆盖完整源码、既有历史登记及成果、运行环境、时间和内存门槛、评估指标与停止条件；确认 Git HEAD、工作区、源码 blob、默认 Bot 和历史来源身份。历史复算证明只在认证输入内容、来源角色和分片顺序完全一致且无并发替换时复用，不代表本入口重新完成了逐组语义复算。本地事前登记不是第三方时间戳。

调用方还需要在代码仓库之外的本机 artifacts 目录独立预先固定私有合同和它的 SHA-256；合同包含历史私有收据摘要、目标设备身份、批次随机数，以及已事前核验的解释器、独立虚拟环境、base、完整有序搜索路径与依赖允许来源。路径均使用预先解析的绝对路径；调用方须在冻结前实际审核来源，期望摘要不能在运行时从同一待核验合同现算现用。这些内容及其摘要、私有来源、观察、掩码、详细结果和原始模型均不能发布。私有目录仅作为本机运行产物，输出目录和文件排他创建，不覆盖历史文件。复制的 baseline 原始 checkpoint 可能包含旧元数据，必须按私有文件处理；schema 字符串亦须在发布前单独审查。

私有合同的 `runtime_identity` 使用 `venv_executable`、`interpreter`、`venv_prefix`、`base_prefix`、`search_path`、`allowed_origins` 六个字段；`venv_executable` 是未经解析的虚拟环境 Python 绝对路径，`interpreter` 是该路径解析后的目标。后两项是数组，搜索路径有序，允许来源是虚拟环境内经审核并出现在搜索路径中的目录。将来启动子进程时通过 `child_interpreter` 取得并使用前者作为 argv[0]，不能将解析后的 base 可执行文件代替虚拟环境入口。入口只是核对这些预固定值，不替调用方验证它们在登记前如何产生。

正式运行应由事前登记和认证的外层监督器启动并最终确认退出、超时与一次性收据；本子进程不负责启动该监督器，不认证管道写者 PID，也不能用自身收据代替外层确认。输出 `child-result.local.json` 的 `supervisor_confirmation` 始终为 false。登记必须包含 gate、TERM、清理与外层总时限，入口会验证其大小关系；尚未实现的外层监督器仍须实际执行这些时限，不能将格式检查当作监督通过。GPU 设备、进程环境和已绑定导入来源须由入口及外层共同核实。采样 `/proc/meminfo` 的 `MemAvailable` 和阶段时间用于中止检查，不是 cgroup 或显存硬限额；外层进程监督仍不可省略。实现依赖运行期间源文件、输入和 Python 导入环境没有同用户并发替换，文件与目录检查并不是操作系统锁。

依赖导入前核对私有环境身份、完整搜索路径、发行版本和代码列出的所有依赖根的可发现 spec；非核心依赖可以不存在，已存在时其所有发现路径必须获准。入口拒绝已提前装载的核心依赖及其子模块，并先检查其他已装载的已列依赖来源；这无法补救启动阶段已执行的代码。导入后、GPU 插件加载后、训练后及结束前再次检查已加载的 NumPy/JAX/jaxlib/Optax、CUDA 插件和列明的常见依赖来源。namespace 检查全部搜索位置，jaxlib 无 spec 的原生子模块须绑定到已检查的扩展父模块。该检查覆盖代码中列出的依赖根，不保证列出了所有间接依赖；它不认证 wheel、系统库或第三方供应链，也不能证明 Python 启动阶段 `.pth`、`sitecustomize` 等代码未执行。导入钩子与同用户并发修改也不是本门禁能消除的信任问题。

项目代码使用守卫明确列出的预导入来源集合；调用方须先逐项核对该集合的登记、Git blob 与工作区字节，集合缺项在项目模块导入前失败。该集合只覆盖事先列明的模块和受控后续导入，不是对任意动态导入的形式化闭包证明。

候选流程按顺序绑定历史证据及私有收据，复用原加载器认证三个开发来源与训练来源，核验旧、新来源顺序和本机掩码，然后从已认证的单次有界字节快照加载旧模型。两臂使用共同批次、相同初始化和归一化，各进行 64 次、每次 256 组更新；控制臂使用原 CE，辅助臂叠加系数 0.25 的同目标工人损失。辅助项独立梯度范数超过 `1e-8` 的更新至少 32 次。最终私有 checkpoint 排他写入后，要求真正经原 `TaskNetwork(path, sha)` 重新读取，对参数、归一化和 schema 做核对，并逐组检查实际 CPU 打分及首个最大值与分块评分精确相等。此项只约束同次运行的 CPU 路径，不表示不同硬件或执行环境必然逐位一致。

开发筛查与技术执行验收分开记录。三个来源分别计算全部组和训练未重合集，同一来源先在簇内求均值再对簇等权，比较旧模型、控制臂和辅助臂。事前固定的主指标为三个来源的未重合 PLANT 同目标工人 top-1：辅助臂相对控制臂的三个来源等权平均至少 +1 个百分点，且每个来源不能低于 −2 个百分点。完整候选 top-1 与目标加操作匹配是护栏，分别对每个来源和两个子集检查，辅助臂相对控制臂以及相对旧模型均不能低于 −2 个百分点。

每项指标仅在至少 20 组、至少两个簇且该来源每个预期簇至少 5 组时才为 supported，否则为 unknown。任何筛查必需指标 unknown，筛查结论就是 unknown，不算通过或失败；其余为 passed 或 failed。技术子进程收据仅说明执行与技术门槛，开发筛查通过也不构成教师晋级、官方对局改善或独立测试证据。所有精确指标与分来源结果只写私有文件。

## 当前验证范围

`test_entry.py` 只使用内存中的合成数据、模型和模拟 I/O，在 Windows 和 WSL 的 CPU 环境下验证登记门禁、预算、搜索路径顺序和 shadow/namespace 拒绝、导入闭包拒绝、来源调换、筛查、既有结果目录保护及阶段顺序。测试里的 GPU 设备、64 次更新、私有文件和模型重载都是注入对象，不是真实设备、训练或磁盘重载；真实模型由 `TaskNetwork(path, sha)` 重载的代码路径仍须在正式私有产物上实际验收。现有独立的内存流水线还做过 2×8 合成 CPU 更新，不证明 64×256 实际训练可行。

后续依次完成外层启动器与守卫闭包、独立复审、严格的公开与私有登记，然后才可考虑一次正式执行；真实结果返回后先做脱敏和证据复审，再决定是否进行新留出官方完整对局。本阶段不启动游戏、BC 新训练面板、DAgger 或 PPO。
