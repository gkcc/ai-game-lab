# 两臂训练进程监督：合成阶段

本组件接入新的 `task_pair_pidfd_guard_v1.guard` 和既有 smoke 监督器的非阻塞有界收据管道；不修改历史 `gpu_guard`，也不自行启动训练。未来外层必须事前独立固定并认证命令、源码及 `Contract` 中的 gate SHA、工作限额、TERM 阶段、清理限额、门等待限额、含清理监管总限额、完成步数和辅助梯度非零次数门槛。工作限额与清理限额之和不能超过登记的监管总限额；组件不预设 64 步或实际训练预算。守卫实际从有界校验的一份 gate 源码快照启动，核验 leader pidfd、PID、SID 和 starttime 后才放行目标。它不向数值 PID 或 PGID 发信号。

返回值分别标记工作轮询中观察到的退出、退出码为零、规范令牌收据、登记步数、辅助门槛、两臂状态、守卫报告的两次空扫描、直接子进程已回收、pidfd 已使用、组合的会话清理标记、工作限时触发、监管含清理总时限，以及收据出口尝试和接受情况。只有以上相应成功条件、最终取消采样与收据出口均通过才返回 `passed=True`；缺失或不符合规范的守卫报告不能当作通过。守卫异常抛出脱敏错误，清理未确认。空扫描是有界采样，不能证明抵御恶意并发；它不覆盖脱离 session、不可中断进程、系统崩溃、强杀监督器或并发 reaper。守卫错误后未知后代可能仍存活，外层必须停止并按未确认清理处理。

每次尝试须在启动前私下独立生成并固定新的密码学随机 32 位十六进制令牌，调用者负责本机安全留存、身份认证和不能覆盖的独立登记；语法检查不能证明随机性或唯一性。子进程以 `--receipt-token` 接受令牌，并输出唯一规范 JSON 收据；管道最多接收 4096 字节。只有子进程、登记计数、收据、会话清理和总预算通过，且清理后取消采样未见请求时，才在 stdout/stderr 静默范围内调用事前认证的 `receipt_sink(raw)`。参数是准确的不可变原始 bytes。sink 异常或返回值不是严格的 `True` 均不通过，异常内容和原始 bytes 不进入公开结果。调用者的本机 sink 须对该次私有文件排他创建、对字节数设限、写入并有界读回核对后才返回 `True`；组件只记录回调自报接受，不能独立证明文件写入。

出口执行后再次采样取消；若发现取消，最终不通过，即使本机已经留下规范收据。仅有原始收据不能当作成功运行凭证。令牌收据是子进程自报，管道不认证写者 PID，也不是第三方证明；同用户进程的伪造及令牌泄露不在防护范围。外层仍须认证登记链、源码、数据、模型和设备，并独立保存脱敏最终状态，不能仅凭收据宣称真实训练、GPU 使用或比赛表现。

工作期限按守卫采样，首次观察到退出时若达到或超过工作期限即保守判超时；即使实际提前退出但观察较晚也可能失败。守卫耗时从其内部启动点计到清理和直接回收之后，不含此前导入、源码校验、能力检查，也不含 sink 或外层全部启动收尾；没有单独测量清理阶段。外层必须对整体进程另设预算并核查结果，不能把守卫的登记总限额说成端到端硬实时保证。

本组件必须在 Linux 主线程运行，以安装和恢复信号处理。`SIGTERM`／`SIGINT` 转为取消请求；启动前、清理后和 sink 后均采样，已观察到的取消覆盖成功。采样与启动、放行或返回之间仍有竞态，不能保证任意时刻的取消都阻止创建，也不是精确的取消时间戳。未启动时不声称清理或耗时已确认。外层须等待 Linux 监督进程退出；杀掉 `wsl.exe` 本身不证明 Linux 子进程已清理。
