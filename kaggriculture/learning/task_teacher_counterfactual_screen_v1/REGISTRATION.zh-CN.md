# 已消费教师分歧：完整请求与官方单步预筛

本阶段只寻找值得另行研究的历史分歧，不运行完整新比赛、不训练、不调用 GPU、不使用 PPO，也不改变默认 Bot、旧模型和历史结果。状态残差原筛查仍是 failed；即使本阶段候选数足够，也只允许之后另行审查和登记完整配对实验，不自动开赛或晋级。

## 来源与预先选样

使用认证过的 Anchor baseline 已消费 A05/A06 两个角色、market/round2 对手及双方学生席位，共八个固定来源。真实角色 A05/A06 在第二批来源中分别映射到内部固定槽位 T01/T02；既有 `game.scan_candidates` 的坐标排名使用 T01/T02、对手、席位、step 和 ordinal，而非 A 别名。源读取器检查官方规则、冻结任务/选种模型、逐场收据、完整 Replay，以及同一文件描述符前后摘要和 719 行 trace 语义。回放与原始观察、种子、具体候选 ID、路径和权重均不公开；来源绑定仅解析已完成映射，不打开未消费种子清单。

每场先构造完整私有计划：六个窗口 0–119、120–239、240–359、360–479、480–599、600–718，各取既有固定排名的前两个不同 step，窗口内和窗口间保持该固定顺序，不按比较结果、动作、市场或未来收益换点。既有扫描器先在每个 step 的分歧 ordinal 中取最小哈希，再将 step 按该最小值排序；因此同一步分歧越多越容易入选，不能称 step 均匀盲抽。原扫描器最多返回每窗前四个不同 step：记录前两名的空位、未检查及每种结果，单列第3/4名的数量；低于前四的其他分歧总量未知，不重复扫描或猜测。每个来源达到第一个符合条件的候选即停止该来源的后续检查，已选但未检查的名额明确保留。条件筛选和提前停止意味着这些计数不是全部历史分歧的自然发生率。

## 对照与判据

冻结 `compare_turn` 从同一单方观察、上一回合模型预算和历史完整请求出发，先重建学生事实，然后只在一个预选 callback 强制当前条件教师候选，后续仍使用相同学生。资源不足、来源或对照不一致停止；内部不确定记录为 unknown，不当作相同或成功。完整有序比较与官方 `same_request` 的字典顺序和零值口径不同；若前者报告不同但后者判断请求相同，单独记录，不运行官方单步，也不声称未来状态一定相同。

仅对官方请求口径不同的案例，调用原 `official_step.compare_step`；它使用认证的历史双方请求和原引擎，先复现事实下一帧，再计算替换请求的下一帧。条件是该 helper 的现有 v2 canonical 加 Python 等值比较检测到**非动作下一帧语义不同**；它仍包含状态、奖励和观察等，不限定为资产/位置的物理变化。该比较会把 `True`/`1`、`1`/`1.0` 视作相等，且忽略普通字典（包括 shed）的顺序；未检测到差异不能排除仅类型或普通字典顺序变化，也不能证明未来相同。已有的是合成反例，不宣称真实案例发生上述差异。双方之后的行为、共享市场与随机流均未在此运行；任何单步差异不证明收益或胜率。

每个角色×对手×席位最多保留一个候选。八个坐标中至少四个候选且 A05/A06 均有覆盖，标记 `sufficient_for_separate_design`；否则标记 `insufficient`。这是资源和覆盖条件，不是效果检验、模型晋级或独立泛化。候选的 step、ordinal、当时合法输入的摘要及教师/学生候选 ID 仅封存在本机私有计划，供后续重新认证，不随公开账本发布。

## 资源与封存

上限 96 次 `compare_turn`，每次先预留最多两个完整单回合控制器分支，合计上限 192 个；比较不等于神经网络前向次数。每个控制器的任务/选种次数与输入行还受已认证 `game_limits` 限制。调用前预留和记录比较 begun/completed；不插桩冻结 compare 内部，实际控制器分支数为 unknown。仅官方请求不同时才预留两次单步，记录 helper begun/completed；只有 helper 完整返回且通过返回合同后才确认两步完成，中途异常不猜测已完成第几步。失败时保留调用方持有的计数快照，若失败收据本身无法写入，不再声称准确数量。

`prepare` 只在指定父提交、工作区符合要求且初始可用内存至少 5 GiB 时绑定已完成来源和模型身份，不读取游戏、不前向；源码和登记必须随后提交推送并通过独立预审，才可执行一次 `run`。登记 Python 三位版本及 numpy、kaggle-environments、psutil 发行版版本，受管 child 在开始及封存前校验不变；源码摘要仍是身份依据。登记绑定静态扫描到的本仓库组件及历史冻结运行组件，包括由 `TaskAgent`／`CropAgent` 按 SHA 动态加载的教师源码；来源适配器另核验对应本地运行副本和模型。静态图不能证明所有动态导入、解释器或第三方包内容均已覆盖。受管 child 扫描前和封存前分别核验实际安装的官方游戏规则和框架 core 文件摘要，即使没有进入任何官方单步也要检查。运行采用现有 Windows 命名 Job、单子进程及 no-retry：运行采样可用内存下限 4 GiB、RSS/commit 2/3 GiB、时限 900 秒、磁盘至少 4 GiB 加预留。约束是采样和协作式检查，不是硬实时保证。每场离开来源上下文后释放 Replay；异常不重试，不生成成功封存。公开仅能发布经隐私检查的匿名覆盖与汇总，不包含私有计划或候选原文。
