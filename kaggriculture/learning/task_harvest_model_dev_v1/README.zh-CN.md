# 冻结双模型的收获选择开发验证

本目录将已验收的原地甜瓜 WATER／HARVEST 候选扩展接到既有任务模型，保留同一个选种模型。它不训练，不修改冻结教师、默认 Bot、模型、官方规则或历史结果。

`policy.py` 复用原 BoundedAgent 的完整回合顺序和计算限额，并复用上轮虚拟槽消费。任务和选种检查点均须提供并校验 SHA；选项直接服从当前任务网络 argmax。新增 `task_model` 记录取自同一次前向的结果，不为日志再评分。精确平分仍由原候选前缀获胜，没有价格／仓容合法性屏蔽或额外收获偏置。

`precheck.py` 在四个已登记中局原点检查原双模型与禁用扩展的整请求、原候选、选种和资源预留；另比较原池／扩展池评分。中局不伪造 step=0，不补跑前缀：直接控制器调用显式计费，原历史累计计数与当前单次计数分别保留。所有真实推理都在提交冻结后的唯一 run 内，准备和纯回归不读取权重进行计算。

四个来源为已消费 C01/S02/market/席0、C01/S03/round2/席1、C02/S02/market/席1、C02/S03/round2/席0。父进程按既有 completed-source loader 认证旧32场的收据和压缩文件身份；不搜索种子库存。另从已封存四条 48 步事件流各读取一次，核 SHA、CRC/EOF，提取固定原点，不再选择新点。旧事件流本轮只用于输入身份，后续收益不传给模型。

前置通过后四场新完整比赛各做一次 Actor 重建与官方主复演。原 Worker、现金消费者、公开／私有状态和背包／仓库顺序检查继续使用。现场、重建和官方复演分别记录尝试和返回；预期 8 次环境构造、12 次初始化、5,752 次官方动作。前置另计 8 次控制器调用和 8 次评分。无额外旧学生 parity 轨迹。强制终止或写入失败造成的计数收据缺失按未知／失败处理，不作为零次执行或通过证据。

运行入口为游戏虚拟环境的 `python -I -B runner.py prepare`，完成独立审查与本地登记提交后 `python -I -B runner.py run --registration-commit <完整登记提交>`。准备和运行均排他写入；失败保留证据，不自动重试、换点或改阈值。

四个匹配子进程串行使用现有 Windows Job 监管，初始／间隔可用内存至少6 GiB、运行至少4 GiB，RSS最多2 GiB、commit最多3 GiB，每Job最多900秒；总运行最多两小时，新产物合计最多1 GiB。前置检查在协调器内使用相同内存与计算检查，未宣称有独立OS监督。原件、权重身份和逐步执行明细只保存在本地；公开结果经明确字段白名单，只含必要聚合和历史对照。

成功仅证明冻结权重能通过扩展接口控制官方完整比赛。若始终不选新增项，如实报告无新增动作控制证据。四局与旧 baseline 是历史开发对照，不是同期成对收益估计或独立留出，不作统计晋级。旧教师单标签和先前短窗口现金差都不作为新增 HARVEST 的训练标签；不启动 BC、DAgger、PPO 或 GPU 训练。
