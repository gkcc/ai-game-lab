# BC 实验准备入口修复

起始提交为 `58adacb72af40be52779b322f371039d00afabdb`。原准备脚本固定生成 19 个种子，又拒绝任何已经公开的种子；发布原登记后，新目录准备必然失败。

本轮新增 `prepare.py` 入口，不修改历史冻结的 `experiment.py`、`analyze.py`、模型、默认 Bot 或原策略。新入口只创建登记、保护清单和参考策略副本，不自动训练或比赛。运行命令见 [README](README.zh-CN.md)。

## 修复与边界

- `new-holdout` 必须提供明确种子 JSON：8 训练、2 验证、8 测试、1 等价验证；严格整数范围及全分区互斥。空文件、缺参数、不合法配置不会采用默认或历史种子。
- 新颖性检查覆盖当前公开跟踪文本，以及本地登记、账本和结果等 JSON。它是保守的十进制出现检查，可能拒绝无关数字碰撞；不证明外部、已删除或仅原始回放中从未使用该种子。
- `historical-replay` 必须指定原登记，不接受替换种子；绑定原规则、教师、对手和 Worker 源码身份，沿用训练与统计设置。其含义是同配置复现准备，不是恢复历史机器和源码检出。
- 历史登记不得直接作为新留出模式的验收模板，防止“历史描述”和“新独立证据”标记矛盾。
- 所有正常输入校验在建立输出目录之前完成；目标已存在即拒绝，不覆盖已有结果。磁盘写入阶段的 I/O 失败仍可能留下不完整的新目录，不能将其视作准备成功。
- Windows 检出的规则文件只有 CRLF/LF 差异；先对照固定提交的 Git blob，再检查已安装游戏引擎的原始 SHA。Git 输出明确按 UTF-8 解码。

报告包装器只增加解释层。历史模式在写结果之前将新独立聚类数设为 0、`imitation_B_passed` 设为 null，原门槛数值结果另存；不改变收益、bootstrap、A 门槛或模型。旧登记的两份统计结果保持原有结构和数值。冻结 `analyze` 是历史计算模块，新流程只使用 `report` CLI。

## 验证范围

9 项针对性回归覆盖：配置合同、公私历史碰撞、旧种子/缺参数/空文件拒绝、历史模式与防覆盖、历史参考不能晋升、新配置真实 CLI、参考源码身份、报告角色合同，以及已公开 144 场账本在临时副本的历史/旧版解释重算。

此次没有训练、没有新比赛、没有重跑 218 场。收益重算使用现有账本的临时副本；原账本和证书原字节保留。新旧准备入口都不代表用户已授权执行下一轮训练。

旧官方源码检出、模型、默认 Bot、历史文件和冻结清单另做哈希核验；子代理独立复审及隐私检查见 [本轮验收证据](../../../review/evidence/bc-prepare-repair-20261023/acceptance.json)。原始失败日志、机器信息及临时准备目录均不发布。

本轮止于入口修复，不启动 BC 重训、DAgger、PPO、自博弈或市场版预留面板。
