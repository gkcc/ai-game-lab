# 稳定 trace 修正后的另一个开发案例

旧 `S01`／市场版／0 席的 v1 尝试因把 `inference_seconds` 当作确定性轨迹字段而失败，证书、原始文件及代码均保留，旧尝试不重试。v2 修复控制 trace 和干预前缀两处比较，仅将顶层 `crop_records[*].inference_seconds` 的数值规范化，保留该键及其顺序；控制局全部回合及干预前完整回合中的其他字段和其他路径上的同名字段仍按有序语义比较。目标回合另按下文所述核对决策时字段。旧失败证书提出使用递归 `stable`；v2 采用更窄的过滤范围，避免无意忽略其他位置的同名字段。

这是另一个开发案例，不是新的留出测试。历史面板结果已知；固定同一个已消费角色 `S01`、不同的 `round2` 对手、0 号席位、零基 step 2 的第 6 条任务选择记录，不按本实验的未来结算再挑场。同一 seed 不构成新独立样本。保留历史对局 `A`；先从官方初始状态重新运行未干预的 `A′`，只有它与 `A` 的 720 帧公开及私有语义状态、719 次保序完整请求、背包及仓库顺序、稳定 trace 和最终奖励一致，才运行干预轨迹 `B`。状态比较排除 `remainingOverageTime`、忽略普通对象键顺序，不能称为回放原始字节一致。

`A′` 与 `B` 都使用冻结的合并任务模型、同一作物模型、同一冻结对手、同样的预算及官方引擎。模型在每次调用仍正常预测一次；仅在指定选择的合法可观测输入与历史记录一致、原预测和候选身份都匹配时，`B` 将该次返回 ID 换为当前条件教师的候选。完成该回合后、请求送入引擎之前核对动态教师标签、单次触发及与 `A′` 的目标回调预算一致。其余选择完全使用原模型；模型不得获得对手私有状态、回放未来轨迹或种子。

赛后检查 `A′` 和 `B` 的共同初始状态、干预前双方完整请求以及目标时刻的完整有序输入和预算。任一前提不成立就停止并保留失败证据。分别使用原官方引擎及既有执行追踪器复演两场，各 719 次转移；按请求、官方执行效果和最终现金分别记录。如果选择被替换但完整动作未变化，或官方动作无效果，也保留负结果。两次新对局加两次同引擎复演最多 2,876 次官方转移，不训练、不修改默认 Bot 或冻结策略。

目标前已发生的作物选择记录按目标回调的预算计数截取，并在 B 对局后核对 `CropAgent.select()` 当时写下的输入、选择和其他字段。`unit_request` 与 `buy_seed_orders` 是整回合完成后才追加的字段，可能受目标之后的安排影响，因此不用于断言目标之前已经一致；完整动作仍经官方复演核验，但这不单独证明每份市场订单成交。若目标前选择字段不一致则丢弃该局结果。此项是赛后检查，不声称当时就能阻止已经提交的动作。

两场比赛各在独立 Windows Job 中运行，子进程标准句柄通过明确的继承列表连接 NUL；Job 的内存测量是采样，不是硬内存上限。两次官方复演在外层运行器内执行，不属于上述比赛子进程 Job。目标的条件教师标签在整回合完成后、动作交给引擎前核对；若标签不符，同回合可能已经做过后续模型预测，但不会提交该回合动作。

两个轨迹的随机种子和初始条件相同。官方每个日终按种子和日期重新初始化随机数，但杂草抽样只对空地消耗随机数；若当日状态不同，同一日终随后另一方的杂草和城镇抽样也可能变化。后续日终重新初始化后，状态差异仍可能改变抽样次序。因此这个案例最多给出固定初始条件、固定后续双方策略和官方状态相关随机机制下的一次干预总效果；它包含后续任务再分配、市场反应与随机流变化，不能拆成纯距离收益或解释历史面板的整体亏损。一个案例不足以证明显著性、泛化或直接重训；后续需另选更多开发局面和真正未消费的新种子评估。

原始回放、trace、种子、输入快照和本机路径只保留在本机独立实验目录。正式代码、脱敏汇总、验收条件和必要的审查证据才可提交公开仓库。

准备入口按原登记的逐文件原始字节摘要核对公共运行时；其中部分文件为 CRLF，不能统一换行为 LF 后再对比原摘要。若其他检出方式改变了这些字节，入口会拒绝，需恢复与登记一致的源码后再运行。

准备、运行器与比赛子进程在加载项目模块前复用既有包遮蔽检查，并固定项目命名空间；`-B -I` 加全新且不创建的字节码前缀避免读取既有项目缓存。这些检查不抵御同用户在校验后并发替换文件或任意自定义加载器。
