# 已冻结任务模型的采样诊断

本工具只研究已有训练器的入批规则，不训练模型、不执行推理或比赛。历史训练没有保存逐批索引或随机状态；这里的 128 次入批是依据冻结源码、档案顺序、登记的 NumPy 版本和 RNG 初始化过程所做的**条件重构**，不是当时入批的直接日志。结果不能证明模型精度或比赛收益变化。

工具验证历史登记、结果、相关源码与两份训练档案的字节摘要。训练档案按旧数据在前、新数据在后的原顺序使用；每份档案以限长的同一内存快照完成摘要检查与后续解析，仅解码 `offsets`、`teacher_choice_label`、`ops` 三个成员。为校验摘要会读取整个归档的原始字节，但不解码特征、游戏种子或模型权重，也不读取留出轨迹。格式、形状、整数类型及 NPY 头在分配数组前检查。

旧采样先消耗与网络初始化相同的三组 NumPy 正态抽样，再对全部组做排列；它跳过会使整批 padding 超过预算的组。对照使用同一主种子派生的另一个伪随机域，每步抽取与重构旧批相同数量的完整组，并按既有微批桶规则计算形状工作量。它是一次有限的伪随机对照，并非历史实际抽样，也不保证有限样本的类别占比等于理想均匀抽样的人口占比。

输出分别汇总旧/新来源、教师选中的操作、候选组宽；同时给出入批次数占比和各更新中等组损失权重的平均占比。后者仅是目标函数权重口径，并非实际梯度贡献。人口占比是理想均匀抽样模型下的期望；padding 单元与微批个数只是形状工作量指标，不是 GPU 耗时、显存或收益。新示范原本已按类别偏采样，候选特征的标准化也按候选行计数，因此组采样均匀不代表整条训练流程或真实游戏分布均匀。

每个汇总维度若存在 1–19 组的类别，则整维不发布；极小的未选组和跳过次数也不输出具体数量。这是减少差分披露的措施，不是形式化匿名保证。汇总不包含真实种子、组编号、训练索引、原始输入或本机路径。

在仓库根目录、配置好项目虚拟环境后，可将 `GAME_PROJECT` 指向本机游戏项目根目录，将 `OUT_STAGE` 指向其 `artifacts` 下尚不存在的新目录，然后运行：

```powershell
python -B -I kaggriculture/learning/task_sampling_diagnostic_v1/analyze.py --game-root "$env:GAME_PROJECT" --stage "$env:OUT_STAGE"
```

结果先写入新目录的 pending 文件，重读确认后原子替换为 `summary.json`。验收仍须同时检查进程退出码为 0 和完整 JSON，不能仅凭文件存在。程序对归档快照、解压总量和各元数据成员设上限，并在部分步骤检查时间；这些不是操作系统级 RSS 或硬时限。源码和数据校验不防同用户在其他未受保护位置并发改动。
