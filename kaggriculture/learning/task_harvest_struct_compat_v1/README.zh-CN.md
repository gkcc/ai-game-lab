# 官方 Struct 比较兼容与原四点技术复现

本包处理单步诊断已经定位的接口错误：官方返回的 action 使用 `kaggle_environments.utils.Struct`，原严格请求比较器只接受普通 dict。只对已认证的确切官方类型创建比较副本，随后仍使用原比较器。标量类型、有限数、字符串键、列表／市场顺序和原状态保序检查均保留。转换不写回环境或请求，也不改变 Agent 策略。

`runner.py` 从冻结 runtime_v2 协调器字节创建独立命名空间，复用原四点 Windows Job、一次性许可、内存、输出预算、失败结案和完整消费者。只重绑当前路径、登记／来源认证、准备和 `window_worker`。没有沿用单步诊断中“原 case 失败但诊断成功”的验收分支；本阶段的四个完整窗口必须各自真正通过。旧共享模块、策略、模型、默认 Bot 和历史证据均不改。

`contract.py` 可在 bootstrap 之前按固定 SHA 快照，只依赖标准库定义；结果投影在执行入口初始化之后延迟复用原信号门。`compat.py` 与 `worker.py` 负责确切类型、冻结 core 独立命名空间和实际首步的验证。

## 准备与来源

`--prepare` 原样复制 runtime_v2 登记的四个 source/selection，包括 JSON 对象顺序和逐文件字节，不重新择点。先认证 runtime_v2 失败的 18 份原件和单步诊断的 18 份原件、各自外置盐承诺及结案关系。旧事件文件只做字节身份核对，不解压或扫描。两轮各一次官方转移保持为历史累计 2 次，不改判旧失败。

准备通过安全 metadata 入口认证已完成 32 场的登记／收据，以及模型、源码和默认 Bot 的资产哈希；`verify_game_files=False` 明确表示此时不重读历史压缩 Replay/trace。官方 utils 字节按固定 SHA 认证，不导入官方运行包。准备不构造模型或环境，不运行推理、选择器或官方转移。preflight 和正式运行的父进程再核对 32 场完整压缩文件身份。

新来源闭包从单步诊断登记的 484 项延续，增加其登记、已发布结果和本包。`PROGRESS.md` 只接受 BASE 已有的完整追加前缀，其余旧文件保持原 SHA。运行后的公开结果另存，不能修改登记或原件。

## 运行与验收

先在独立审查通过后准备；将源码、登记、测试和中文说明脱敏提交冻结后，才以真实冻结提交启动。每次命令必须退出 0，才进入下一步：

```text
python -I -B kaggriculture/learning/task_harvest_struct_compat_v1/runner.py --prepare
python -I -B kaggriculture/learning/task_harvest_struct_compat_v1/runner.py --preflight --registration-commit <冻结SHA>
python -I -B kaggriculture/learning/task_harvest_struct_compat_v1/runner.py --run --registration-commit <冻结SHA>
```

每个原点先运行并验证 48 步事实臂，再运行一次单单位收获请求替换的 48 步干预臂。首个 F01 官方事实步和原 EventSink 必须完整通过，才进入第二步；该步已含在 48 步内，没有额外探针。最多四点、八臂、384 次新官方转移。单臂模型限额及所有前缀计量保持原值。

启动／案间可用内存 6 GiB，运行底线 4 GiB；每 Job 900 秒、RSS 2 GiB、commit 3 GiB，总时限两小时。单案写入上限 128 MiB（其中保留原 1 MiB case 结案空间），阶段实际输出在既有检查点及验收时核对不超过 512 MiB，私有结果 16 MiB。内存采样不等于连续监测，阶段输出检查不冒充系统硬磁盘限额。

旧 close helper 在已有原异常时保留原异常；没有原异常时结案写入失败仍失败。失败原件保留，目录不可重试；未完成点不补零，也不输出部分面板均值。

全部四点技术验收后，才报告各自 48 步自身现金、对手现金和相对差。原四项研究信号门不变，完整结果即使不满足也如实保留；门不通过不能解释为收获无价值。四点是已经消费的开发点，本轮只属兼容修复后的技术复现，不是独立测试、完整比赛、正式训练标签或模型晋级。没有新种子、GPU 训练、BC、DAgger 或 PPO。

## 针对性回归的范围

`test_runner.py` 使用纯内存档案和真实 `-I -B --help`／metadata 快照入口，覆盖双来源中的诊断原件保留、失败 case 不改判、来源链不匹配拒绝、四点字节顺序不变、禁止重新择点／读游戏、隔离模块不污染旧全局、原预算以及结案原异常保留。官方 utils 哈希变化会拒绝。
