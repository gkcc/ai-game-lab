# 任务头排序开发比较：独立登记与字节比较修正

本目录为独立的 v2 登记准备。v1 的唯一一次尝试及历史材料继续保留，不覆盖、不重跑旧入口。原尝试只记录了 `ValueError` 等有限外层信息，未直接保存逐步骤证据；v1 对工作区登记单侧转换换行的代码存在可合成复现的反例，但这不足以证明它就是原失败的唯一原因。

v2 修正登记身份核对并增加结构化执行契约与脱敏失败阶段；数据范围、模型和原有评价门槛不变。Git 提交对象中的登记字节必须与工作区登记字节完全一致。两侧同为 LF 或同为 CRLF 均可；哪怕只在换行不同，也必须拒绝。入口要求完整提交 SHA 等于当前 HEAD，并在运行前后复核。登记解析使用已通过字节比较的同一份工作区快照。

v2 先以固定 SHA 校验并在独立命名空间加载冻结 v1 入口，先验证 v2 独立 schema 和包含全部 v1 与 v2 文件的精确源码集合，再临时投影到 v1 格式，调用原有来源、预算和源码校验。现有官方规则、Bot、模型、数据认证、资格门槛、评分逻辑、脱敏输出及 pending 发布设施均复用 v1；结果和登记使用 v2 身份，输出目录独立。

登记使用严格的结构化执行契约，逐项核对筛选条件、覆盖门槛、模型方向、指标、联合护栏、全部编码回合范围和内存门槛，并区分整数、浮点数和布尔值；解析时拒绝重复键与非标准数值。源码及契约检查不能证明所有说明文字、历史来源或运行中的并发状态；文字解释不作为程序验证通过的依据。

数据范围、四簇资格门槛、最大评分调用和候选行预算、采样时限与内存预检均与 v1 相同。仍是已消费示范上的探索性比较，条件排序不等于正式动作、收益或独立测试；五组并非五场独立比赛。公开的统计指标只包括主指标配对粗档和探索性联合护栏，不保证形式化匿名。原始数据、真实种子、模型、坐标及逐步状态不公开。

本目录准备期间只运行合成回归，不读取真实档案、模型或种子，也不执行真实比较。v2 需另行登记、检查源码身份并在真实读取前提交；本地 Git 登记不构成第三方时间戳。前后身份检查不是操作系统级锁，既有模型校验与加载分开读取、采样截止不等于硬限制的边界仍然存在。

正式唯一尝试前，操作方须单独只读核对真实 Git 登记对象与工作区登记的原始字节完全一致。该预检不解码数据、不加载模型，也不能冒充正式比较；入口仍会在运行前后自行核验登记身份。

在仓库根目录替换占位符后，使用独立 v2 登记与输出位置：

```text
python -B -I kaggriculture/learning/task_worker_ranking_v2/run.py --game-root <本机游戏项目根> --output-dir <项目根下的artifacts/task-worker-ranking-v2-20261030> --registration-commit <v2登记提交完整SHA>
```

运行者应同时检查进程退出码与完整结果。失败时控制台只显示固定阶段和异常类型，不回显参数、路径或异常文本；进入新输出目录后的失败会尝试保存相同口径的本机失败证书。若目录或磁盘不可写，证书可能无法落盘，仍需保留控制台观察。失败不自动重试或使用旧目录；对被异常中断的运行，不把文件存在或未持久化的步骤当作完成证明。
