# 任务模型开发诊断：指标与执行归因消费者

本目录只提供内存函数。调用方须先认证策略、模型、trace 和完整官方比赛，确认双方动作、719 行轨迹以及 720 个状态，经固定官方引擎 `decision.full_audit.reexecute(..., label_sink=consumer.sink)` 完成保序复演。这里不加载输入、不启动游戏或模型，也不能独立证明调用方提供的证书和身份真实。传入的一局为完整比赛的 actor，评估记录和函数返回值均仅限本机：其中含种子、对手、席位、逐步单位信息与经济账目，不能直接上传或作为模型输入。

`GameConsumer(player)` 通过 `trace_turn` 接收 actor 每回合经认证的 trace，再通过 `sink` 接收复演期间双方所有官方标签；两种输入可任意先后到达。按 `(step, player, unit)` 连接当前模型或教师选择的目标操作、提交的单位请求与官方 `effective/status`，核对 trace 请求与标签的保序、保类型编码。请求可以是移动、等待或其他动作，选择 `PLANT` 不等于已种植。`same_target_atomic_effect` 只描述该次标签是否显示对应地点的原子操作发生；`None` 是缺失证据，不能当作失败或成功，也不能推出任务最终完成、耗时或者收益因果。未找到单位标签时整项执行覆盖为 `unknown`；若本局没有选择也为 `unknown`。官方追踪的状态本身只反映原子变化，不能解释未观测到的长期效果。

经济账复用 `learning.bc_crop_economic_diagnostic.analysis.EconomicConsumer`：记录双方实际成交数量与现金、成功种植、终局种子和仓库库存，并检查期初到期末现金闭合。市场请求数量单独按官方解析的已知数量统计；订单上限丢弃或解析拒绝的原始订单数量标为未知，不推测填零。订单按 `(step, player, order)` 去重。`finish` 强制要求 719 条 trace、双方 `DONE`、复演通过和最终奖励与银行余额一致；调用方仍必须亲自核对官方证书、源码/模型身份和 trace 与回放绑定。期末仓库库存不包括田中作物或单位随身库存；销售收入不是最终净收益。

`CommonHistoryComparison` 以连续的回合接收完整双方回放帧、双方联合请求及各自 actor trace。回放帧先用既有 `decision.semantics.clean` 去除框架时间字段 `remainingOverageTime`（此同名字段在帧的任意嵌套位置都会去除），再使用保序、保类型编码逐字比较；除此字段外不删除任何私有或游戏字段，所有对象和库存顺序仍保留。每次候选模型的完整 `inputs` 则不做这个清理，严格按原样逐字比较其编码字节，包括数字类型与浮点位表示。这是解析后输入的确定性编码，不是原始压缩文件字节逐字相等。首次出现回放帧、同序输入、所选任务、回调次数或联合请求的差异后立即停止，拒绝比较后续轨迹。一次选择不同不证明请求不同；请求不同也不证明官方执行不同或造成收益差异。调用方负责验证双方帧、行动及模型输入对应官方回放；严格帧检查可能因其他无关序列化细节导致保守地给出 `unknown`。

`replay_pair.compare_replays` 接收内存中的两份回放，以及两个已绑定的有界 trace 迭代器。它先检查两份回放各 720 帧、对应种子和配置及双方 `DONE`，再逐回合交错消费两个 trace，每次只保留当前两行。即使首回合分叉也继续排空并检查双方各 719 行、回合次序和错误计数，再各尝试读取一行以拒绝多余记录并触发 EOF 身份核验。比较按下一状态帧中的 `action` 调用既有比较器，遇首次分叉后不再比较。返回结果包含双方策略名、私有种子、种子角色别名、对手和席位，可直接作为 `panel.paired` 的一个 comparisons 项。函数不自行打开文件或认证输入摘要；迭代器本身可能执行调用方授权的读操作，调用方必须限制解压和总读量、保证完整 EOF 摘要检查、异常时关闭迭代器，并独立确认输入属于所声明的冻结模型、种子角色、对手、席位及通过的官方复演。两份回放本身仍由调用方有界装入内存，可能需要的重复读取也必须计入事前登记预算。

`panel.paired` 根据预先给出的种子、对手和双方席位构造完整两策略配对，结果包含逐场自身/对手净收益、现金差、比赛得分、成交与库存，以及 candidate 减 reference 的差值。任一应有比赛缺失时对应组均值为 `unknown`，不填零或删除缺席组。按种子、对手、席位的分组及整体均值均为描述统计；统计显著性固定为 `unknown`，两个种子尤其不能被当作足以证明泛化的独立显著性。这里不选择模型、不启用晋级门槛，也没有因果归因。

待登记的同目标多工人机会门槛固定为：每个完整种子至少 5 次、全部种子至少 20 次，否则 `unknown`。一次机会是一个实际模型 callback 的候选集中，存在同一操作和目标且单位各不相同的至少两项；按 callback 数而非候选数计。`opportunity_support` 分别给 reference 单臂、candidate 单臂、共同历史与严格相同输入的配对 callback 统计，每个口径都须在该种子的全部预定对手和席位上有完整资料。每条配对比较必须显式提供 `reference` 和 `candidate` 两臂身份并与该面板一致；调用方仍须认证这些身份确实对应输入的模型、轨迹和比赛。共同输入配对只计双方均为模型 callback；没有一方完整比赛、比较尚未完成、无比较结果或模型路径分叉后未比较的调用都不补零当成已知机会。另有“实际选择的目标属于多工人组”和“两模型在同输入下选同操作/目标时选择不同工人”的计数，不能混同于上述任何机会门槛。这只是诊断样本是否足以进入后续分析的固定门槛，并非策略晋级、显著性或竞技进步；正式采用前仍需事前登记。

同级 `task_pair_dev_campaign_v1` 包含调用这些内存函数的候选协调器。是否已经完成登记、真实 trace 消费、官方完整复演和经济账本验收，须以对应登记与结果文件为准；调用方仍须证明完整性和输入身份并处理隐私发布，不得将本目录的合成测试当作真实比赛或 GPU 证据。
