# 两个已消费种子的共同前缀诊断

固定已消费角色 `S02`、`S03`，对手 `round2`、双方席位及 `merged`、`unweighted`、`teacher_task` 三个既有策略臂：共 12 场历史对局、4 组三臂记录、8 个配对。两个配对会共用同一条 `merged` 轨迹；这是两个种子簇的探索性历史诊断，不是新留出测试、8 个独立样本或正式收益评估。此前面板经济结果已公开，本次不根据收益挑选场次。

本程序继承原有逐场验收、官方主复演收据、模型/规则身份和保序比较逻辑，并将种子角色加入场次键。对 12 份 Replay 和 12 份 trace 验证既有压缩文件摘要并读到 EOF；原对局、复演及 Windows Job 清理都是此前程序收据，本次不重跑引擎。准备步骤只形成事后私有输入快照，不解码 Replay/trace，也不能单独证明原始验收当时的字节。真实种子仅在本机内存中绑定角色，不输出数值。

首次分歧分类保留本方、对手、同时、状态先不同、终局状态不同及无分歧。共同历史按既有 v2 语义和双方仓库的键值顺序比较；原有 v2 摘要本身保留背包顺序、忽略仓库键顺序，因此新适配器额外绑定双方仓库顺序。只有在这个共同前缀与同一可观测输入下，才比较到该回合的首次任务选择差异；无记录、输入先不同、对手先分叉或状态先不同都不能强行归因。`teacher_task` 使用规则任务选择与共同作物模型，教师标签不是执行成功或最优性证据。角色请求是否相同不代表官方执行或完成；后续现金差变化只是观察布尔值，不是因果分解。

先前 `S01` 诊断使用未额外绑定双方仓库顺序的旧口径，本次不重算或改写旧结果；不能声称三个种子都已按这个加强口径复核，横向比较需保留该限制。

结果中的 `observation_equal` 比较双方完整观测的 v2 语义及仓库顺序，包含现金与双方各自私有观测，并非单纯的物理状态或单方可见视图；相同观测也不保证隐藏随机状态或策略内部状态相同。标为 `24` 的窗口最多经过 24 次动作，临近终局时可能截断；`actions_elapsed` 记录实际动作数。每臂的选择记录数量汇总来自四场，而不是八个独立配对。本次没有新比赛、模型前向、训练、GPU 运算或官方状态转移。

输入角色、源码、输出口径在读取上述历史轨迹前固定。若有缺场、角色/席位/模型/引擎身份错误、收据或原始摘要不符、trace 未到 EOF、预算耗尽或输出无法完整提交，立即停止并保留本机失败记录；不补选场次、不发布部分结论。即使完成全部配对，仍可能无法识别首次差异与任务选择的关联。

受信的已有模块在导入前校验原始字节，绑定项目命名空间并禁用字节码读写；不抵御同用户并发替换文件。累计读取上限为 512 MiB 压缩字节、16 GiB 解压字节，900 秒截止在若干位置采样；这不是操作系统级 RSS 或硬时间限制。原始 Replay、trace、种子、私有状态、输入摘要和本机路径不得进入公开结果。
