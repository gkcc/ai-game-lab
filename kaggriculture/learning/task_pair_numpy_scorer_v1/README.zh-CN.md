# 开发集的逐组 NumPy 评分

`score_blocks` 从现有评估适配器按原顺序读取完整候选组，仅将每组共享特征和候选特征传给已有 `TaskNetwork.score`；返回可由 `evaluate_source` 直接消费的完整 logits 和首位平分选择。标签、种子簇、掩码和组编号不传入模型；组边界仅用于切片。每块有上限，回调可在组间采样取消，未完整消费的结果不能当作有效评估。

调用方须独立认证 schema、原始数据与模型来源，并保证模型权重和数据在评分期间不变。这里复核模型元数据与视图 schema，但不验证权重来源、模型文件加载、特征是否符合可观测性或输入是否被其他代码污染；只读标志不是并发锁。已有开发集已经消费过，未重合子集也不是独立对局或新的留出测试。

迭代开始时，评分器在首次调用外部 `check` 前校验六组参数及均值、尺度的生产形状、浮点 dtype、有限值和 512 KiB 逻辑副本上限，尽可能保留原内存布局并复制为私有只读 float64 快照，再由原 `TaskNetwork.score` 使用快照完成全部分组。回调之后修改原模型的权重或归一化不会让本次结果混用模型；复制期间没有并发锁，亦不能由此证明来源身份或真实文件重载。训练数据和视图本身仍由调用方负责保持不变。

保留布局可以减少某些矩阵运算的舍入差异，但不保证任意非连续视图、其他 BLAS 实现或跨设备结果逐位一致。正式实验仍须对实际从文件重载的模型逐组核对分数和选择，并明确处理近似平分。

合成测试仅在内存创建玩具 `TaskNetwork` 参数和候选组，运行 CPU NumPy 评分并连接现有评估器；不读取真实数据／模型、不使用 GPU 或比赛，不能证明正式模型或实际收益。
