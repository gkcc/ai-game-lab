# 私有掩码来源重算：单次入口

本目录提供一次数据复核入口，与独立的事前登记共同冻结完整源码摘要集合、运行环境、资源预算和停止条件。必须先完成源码及登记的独立审查和隐私检查，且登记提交成为 HEAD，才能进行一次实际尝试。本说明与登记不冒充第三方时间戳，登记阶段不声明已运行。

入口先限定本机项目根下固定的新产物目录，排他创建后才记录启动；然后以已有 V2 方法验证**新登记提交为 HEAD、Git 与工作区登记原字节相等**。旧预检登记 `27635128cee4653e661faeaa16aab28e3d78fc5f` 不当成 HEAD：单独检查它是新 HEAD 的祖先，并比较旧提交、新 HEAD 和工作区中的旧登记原字节。已发布粗结果也检查其历史提交 `54bdf5346e2d76f203edda3d1d91e7d0fac125d6` 是祖先、历史 blob、新 HEAD blob 与工作区原字节均一致。缺任一条件均停止，不读取比赛数据。

新登记的 `source_sha256` 必须恰好包含旧登记的完整来源集合与本入口固定的新增源码集合；历史源码身份不能改变。先逐项有界检查工作区与新 HEAD 中 blob 的大小不超过 4 MiB、SHA 等于登记且原字节相同，才调用旧的源码身份验证；读取数据前及发布前均按此顺序核验。加载旧 V1 入口时只编译执行有界读取、通过固定 SHA 校验的同一字节快照，不二次读取源文件。运行契约限定 Windows `win32`、Python 3.12.2、NumPy 2.5.4 和 psutil 7.2.2，版本不符时在读取数据前停止。沿用旧预检的 `verify_sources`、隔离导入守卫、流式数据身份校验、只读映射、条件档案认证和 `core.analyze`，重新核对历史重合及整个公开粗投影。已有开发数据仍是已消费数据，数值重合不等于完整游戏状态重合。

读取旧清单时计算的 SHA 仅绑定**当前所读的快照**，不能证明它是旧执行当时的原始文件。入口以已认证来源和固定旧／新顺序重算全部掩码，将重算结果逐位与旧快照比较；即使比较通过，也不声称有历史文件创建时间证明。旧数据与旧产物只读，不覆盖。

完成比较后，在新目录排他写入九份新布尔掩码、清单与本机绑定收据；对刚写文件有界读取，用安全头检查和逐位比较验证，不调用旧写入器对文件的无界 `np.load`。收据包含新／旧登记提交及新清单 SHA，只留在本机；脱敏粗结果不含源文件 SHA、种子、掩码、原始数据或本机路径。验收须同时有完整结果、收据和实际进程退出码 0。以后使用前仍须从登记重新认证所有来源、来源顺序、新收据和掩码清单，不能仅凭长度或临时现算的旧清单 SHA。

入口不加载检查点权重、不做模型推理或训练、不新增比赛。只有在安全创建新目录后失败才有该目录内的阶段／异常类型记录；在参数或目录创建阶段失败可能仅有操作端退出记录。已有输出目录禁止覆盖或自动重试。旧预检的内存与时间检查是采样门槛，源文件认证、重算与读回没有操作系统级并发锁；本次证据不能证明无人并发改写文件，也不能证明正式比赛收益。

登记提交并独立复审后，入口调用形式为：

```text
python -B -I kaggriculture/learning/task_pair_mask_recheck_v1/run.py --game-root <本机游戏项目根> --registration-commit <新登记提交完整SHA>
```
