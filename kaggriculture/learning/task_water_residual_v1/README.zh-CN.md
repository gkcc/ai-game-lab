# 浇水候选的有界残差：基础组件

该候选保留冻结任务模型；先按原模型对全部任务候选打分。如果原模型首选不是浇水，直接返回原选择；如果首选是浇水，才在浇水候选中用一个小型可学习残差重排。零残差保持原模型首位最大值规则。这是针对同一候选集合的路由约束；浇水工人或目标改变后，整场比赛的后续状态及其他任务仍可能变化。

输入来自已有数据登记的合法单方候选；规则控制器仍负责生成候选和真实动作。残差输入按 `float32 原始编码 → float64 原模型标准化 → float32`，冻结基线部署打分保持 float64。训练时基线 logits 需转 float32，近似平局可能改变排序；任何真实训练入口必须事先规定并检查该差异。GPU 与 NumPy 的 float32 点积也不承诺逐位一致，须在实际数据上核对数值与首位最大值。

`policy.py` 提供纯 NumPy 重排和与 `TaskAgent` 相容的选择器；它不负责认证 checkpoint、输入来源或用户隐私。包装器的 `last` 是索引，且调用 `score()` 不更新旧 `TaskNetwork.last` 日志字段，故不能未经适配直接接入依赖旧遥测格式的运行器。默认 Bot 不引用本包。

`fit.py` 提供等角色采样与 64 次有限更新的数值核心：只接收调用方已筛出的浇水候选、冻结基线分数和教师标签，优化交叉熵与基线分布 KL。训练先按组减首个真实候选特征；这在精确算术下不改变组内 softmax，可避免相同特征列产生舍入伪梯度，但与部署直接点积的浮点计算次序不同。角色只用于批次均衡，标签只用于损失，不送入模型。调用方仍须冻结和认证真实数据、随机数、模型、设备、超时、内存与输出；仅调用 `fit` 不构成 GPU、独立评估或比赛验收。

`assessment.py` 使用已消费开发角色做逐组配对筛查：每角色准确数不下降、两个角色等权平均条件 NLL 允许不超过 `1e-7` 的数值上浮、净改正至少两组、至少一处实际选择变化且无动作类别翻转。已观察到的翻转或角色退步优先判失败；角色缺失时未确定的细项为 unknown。该筛查只说明在历史教师状态上的有限离线表现，开发样本不是独立比赛；未覆盖任务、未来状态和竞技收益仍属未知。

本包当前仅有纯合成组件验证，尚未登记或执行本包的真实数据 GPU 训练和官方完整对局，不自动晋级、替换模型或修改默认 Bot。正式尝试须另行事前提交源码、数据来源、资源上限及评估口径，并在私有目录封存模型与原始数据。
