# 冻结任务头的工人排序：有限离线比较

本阶段只比较现有两份任务模型在同一批已消费开发数据上的排序，不训练、不新增比赛、不改 Bot、规则、旧模型或历史结果。A 是原 60 场教师示范训练后选出的早期任务头；B 是后续合并教师示范训练的任务头。正式面板里的 `unweighted` 是另一份模型，不用于冒充 A。

两份已封存条件教师档案合计 5,104 个决策组和 322,151 行候选，按各自登记身份、schema 和档案摘要读取。它们各含两个不同的开发种子簇，所有角色仅留本机内存；程序还检查其与早期模型的原训练、开发验证簇不重叠。原教师选择路径与冻结作物模型路径的状态分布不同，档案刻意偏采样：旧来源包含混合行为下的条件教师标签，新来源保留全部开垦和施肥选择、对其他选择固定比例采样。标签表示该上下文里的教师选择，不代表官方已执行或任务已完成。

本阶段选择**所有编码回合**中教师标签为 `PLANT`、同一目标存在至少两个不同工人候选的组，不限于此前四个早期历史案例。先验证整个档案的候选身份、顺序、距离和操作编码。固定准入条件为：合格组至少 20 个、恰好覆盖四个来源簇、每簇至少 5 个合格组；这些是同簇记录，并非每簇至少五场独立比赛。未达条件时停止，不加载两头、不调用评分器。

达标后两个模型分别使用自身冻结的归一化和同一 CPU `TaskNetwork.score`，每次接收该组**全部候选**，同分按原候选顺序决定。主要指标是各簇内教师所选单位在同目标 `PLANT` 候选中的 top-1，先在簇内求均值，再对四簇等权；公开 A−B 的粗档：小于 −20、[−20,−5)、[−5,+5]、(+5,+20]、大于 +20 个百分点。这个条件排序不代表全局实际会选该目标，更不代表已种植或收益提高。

同时计算全候选教师 top-1 与全候选同目标 `PLANT` 的命中率，分别按同样方式等簇加权；只有两项 A−B 都不低于 −5 个百分点时，联合 `global_guard` 才为通过。公开的统计指标只包含主指标差值档和联合护栏，不公开单模型准确率、单簇数、交叉表或精确数值；后两项仅在内存计算，不能根据公开投影单独复算。护栏是事前固定的开发筛查，不是自动晋级标准。

早期任务头的登记训练与验证簇没有包括这四簇，但部分档案状态由早期头参与产生，不能称为完全独立的输入；合并任务头曾用两份档案训练，历史没有逐批组索引，不能断言每一组合格样本实际进入过更新。样本仅来自四个已消费簇，且两来源采样方式不同，不做显著性或因果推断。即使只公布粗档和联合护栏，结合外部信息仍可能推断个别结果，这不是形式化匿名保证；不公开真实种子、单位/地块 ID、坐标、logits、逐步状态、原始档案或模型。

早期模型选取记录到旧缓存及原教师示范登记的历史来源链已在事前由主代理逐环只读核验，两名独立子代理分别核查其中部分关联；入口固定并核对所列登记及检查点身份，也检查两份登记的训练／验证角色一致，但不会在每次运行时重算完整历史来源链。

运行入口核对固定源码、公开来源登记、检查点身份与有序 schema；档案每次按冻结 SHA 从同一内存快照读取。最多 10,208 次模型评分、644,302 行候选评分；开始时采样可用内存需至少 4 GiB，300 秒截止是采样检查而非硬实时或内存上限。结果先写本机 pending 文件、读回核对后改名；应同时检查进程退出码和完整结果，不能只凭文件存在认定通过。源码与模型文件只在运行前后核对，没有操作系统级锁；现有 `TaskNetwork` 对检查点的哈希和加载是两次文件读取，不能排除读取间被并发替换。失败保留本机证据，不自动重试、补样本、换档案或放宽门槛。

本阶段事前来源核对已读取档案字节以校验 SHA 和 NPY 头，也读取模型字节以核验身份；未解码档案数组、解析模型权重或进行推理。登记须在本阶段的真实数组解码和定量模型评估之前提交。以下命令中的项目根、产物目录和登记提交由本机调用者指定；登记仅证明本地 Git 版本关系，不是第三方事前时间戳：

```text
python -B -I kaggriculture/learning/task_worker_ranking_v1/run.py --game-root <本机游戏项目根> --output-dir <项目根下的artifacts/task-worker-ranking-v1-20261030> --registration-commit <登记提交完整SHA>
```

控制器候选本来就受教师经营规则门控，并非官方完整合法动作空间。实际比赛表现和可迁移性仍需要未来独立登记、全新留出种子及完整官方对局；本阶段不做这项评估。
