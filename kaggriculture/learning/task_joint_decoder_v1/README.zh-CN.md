# 当前候选集合解码器 V1

这次只改变冻结任务网络输出的解码方式。作物与任务权重、候选生成、施肥、运输、导航、市场和雇工控制器均不改变。它不是新训练出的模型，也没有扩大现有五类任务机会以外的动作空间。

## 接口与决策

`decoder.choose(candidates, logits)` 返回 `Selection`，包含本次 `choice_id`、暂定匹配的 `matching_ids`、`cardinality` 和 `total_logit`。候选至少带有 `id`、`unit`、`target=[x,y]`、`op`；分数与输入列表逐项对应。

每个回调重新建立“单位—目标地块”二部图，按以下顺序优化：

1. 匹配边数最多，即尽可能给当前有机会的不同单位分配不同地块。
2. 在相同边数内，让原网络 logit 的总和最大。
3. 总和精确相等时，取按 `(unit, y, x, op, id)` 排序后最小的匹配键序列。

同一单位和地块的多个操作只保留分数最高者，等分使用同一语义键。最后只返回所选匹配中分数最高的一条，等分也使用语义键。原控制器实际接收这一个 ID，更新当前资源、工人和预留信息；下一个回调使用更新后的候选重新求解。不会缓存整套分配后绕过控制器的实时检查。

例如当前三条边为 `u0→A=8, u1→A=10, u1→B=9`：逐条最高分会先占住 A；新解码器的暂定匹配是 `u0→A, u1→B`，先返回 `u1→B`。如果后续实时资源变化使 A 不再可用，第二次调用也不会强制执行旧匹配里的 A。

“一个单位、一个地块各至多出现一次”继承现有教师的地块预留政策，**不是官方规则永久禁止同地不同任务**。最大匹配基数也是本候选的分配偏好，不是经济最优的证明。原 logit 表示网络偏好，不等于现金收益；本候选可能执行更多低价值任务，必须由完整比赛检验。

使用最大基数作为第一目标，使负 logit 不会与“未匹配的零”比较后全部变成等待。同一图的固定基数比较，对可精确表示的共同常数平移保持不变。分数必须有限；匹配总分用 binary64 值的精确整数比例计算，避免普通浮点求和丢失微小差值。仅当最终总分不能表示为有限 binary64 时，记录值 `total_logit` 为 `None`；匹配本身仍由精确总和决定。

平局键沿用现有编码器顺序，不能直接使用 ID 字符串的字典序。单单位输入在官方编码器的规范顺序下，与原网络“第一个 argmax”一致；纯求解器对外部输入重排也保持结果不变，这不意味着任意乱序列表的第一个 argmax 是原协议。

## 冻结网络与计费接入

`policy.JointAgent(crop_path, crop_sha, task_path, task_sha, trace=None, limits=None)` 包含原 `BoundedAgent`。每个任务回调只调用一次原 selector，沿用原神经前向、输入行数、作物和控制器预算，然后读取该次 `network.last.logits`；不额外调用网络 `score()`。

读取前清空 `network.last`，并校验本次 checkpoint、选择、分数长度、有限性和原 argmax 一致。失败直接抛错，没有旧分数或教师回退。正式输入仍来自原 `TaskAgent` 的合法观测与候选编码，解码器不读取标签、私有对手信息、种子或未来轨迹。

标准控制器 trace 的 `records[].chosen` 是**实际提交给控制器的解码选择**。新增 `decoder_records` 按同一回调序号保存：

- `original_network_choice`：原网络 argmax；
- `decoder_choice`：本候选返回的 ID；
- `matching_ids / matching_cardinality / matching_logit_sum`：当时暂定匹配；
- `logits`：与该条标准记录的 `inputs.candidates` 对齐的实际前向分数。

`network.last.chosen` 保持原网络事实，不改成解码结果。原 `BoundedAgent` 的文件写入关闭，由外层增补记录后每回合只写一次 trace。每回合清空增补缓冲，step 0 重置沿用的预算与跨局状态；如果目标 trace 已存在，step 0 仍拒绝覆盖。trace 写入失败不能产生成功的 `JointAgent.last`。trace 属于本地运行材料，不因新增字段而获得公开许可。

## 本模块验收范围

在项目 Python 环境下，从 `kaggriculture` 目录运行：

```powershell
python -B -m unittest learning.task_joint_decoder_v1.test_decoder -v
```

16 项合成 CPU 回归已实际通过，其中包含 63 个二单位三目标非空图 × 3 套分数的穷举参考比较，以及第三单位加入后重新分配已有匹配的场景。回归保护最大基数、负分、重复操作、规范平局、输入重排、精确求和和异常拒绝，并通过实际 `BoundedAgent` 预算代码验证每回调一次前向、更新后重算、跨局清空与唯一 trace 写入。

上述包装测试替换了网络和控制器，没有加载真实权重，也没有冒称完整比赛。官方微场景及最多四场完整对局的登记、结果由另行冻结的阶段入口负责；此处不把分配反例当作已获得收益，不作教师晋级或统计显著性结论，不启动 BC、DAgger、PPO。
