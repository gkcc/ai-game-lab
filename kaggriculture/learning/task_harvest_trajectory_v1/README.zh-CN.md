# 收获轨迹解释 V1

这是四个已消费点、八条已完成 48 步窗口的只读消费者。它不加载模型、不创建官方环境、不增加比赛，不更改策略或默认 Bot。原件来自上一阶段已封存的 45 文件；本轮仅派生时间线、账目和信息覆盖结论。

入口为本目录 `runner.py prepare`，冻结登记提交后执行 `runner.py run --registration-commit <登记的完整提交>`。用现有游戏虚拟环境的 `python -I -B`。运行只允许一次；失败保留记录，不覆盖或自动重跑。

准备认证 41 份小原件和外置封存清单，对四个 gzip 仅查大小；这不等于已重验全部 45 文件。正式运行每个 gzip 只打开一次、顺序读至 EOF，在同一读取中完成压缩 SHA、CRC/EOF、行限、解压限额及分析。所有逐步现金增量必须闭合到旧端点；全部四点均报告。

此外读取公开源码、登记／证书，以及本地默认 `main.py` 和固定官方规则源码以核对身份；不会导入官方运行包，也不读取模型权重、旧比赛或额外种子。

统计定义由 `analysis.specification()` 与 `contract.py` 冻结。首个后续请求分歧不含注入首步；分别看本方／对手、单位／市场请求。Top 3 按每步“干预减事实”的相对现金差**增量**绝对值排序，并列取较早步；不按累计差排名。

只有首步有目标单位原子执行记录。后续请求、地块变化、位置与库存变化分别记录，不能当作逐动作成交／执行归因。卖出请求不是销量，余额增量不是销售收入；不分拆价格、产量、调度的独立因果百分比。

公开内容采用显式白名单，仅含匿名角色、窗口账目、有限里程碑和请求类别。原始事件、目标坐标、单位 ID、对手私有库存、实际种子、私人摘要及盐留在本地。复审读取代码和小型派生账本，不对四个 gzip 增加第二遍扫描；此限制会如实写进证据。

资源门槛及停止条件见 `contract.py`：启动和运行可用内存均至少 4 GiB、最多 15 分钟、每行 8 MiB、每流解压 512 MiB、合计 2 GiB、新私有产物 16 MiB。资源检查是单进程协作式采样，不冒充独立系统监督。

学习接口的源码依据见 [FEATURES.zh-CN.md](FEATURES.zh-CN.md)。本轮完成不代表训练准入、独立测试、终局收益改善或教师晋级。
