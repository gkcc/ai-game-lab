# 两臂任务 BC：合成组件阶段

本目录先为一个有界开发消融提供纯函数组件；当前没有登记或执行新的真实训练，也没有新增比赛、读取真实检查点权重或修改默认 Bot。后续若实施两臂实验，必须单独登记完整来源、初始化、归一化、共同批次、优化器、设备、离线指标和停止条件。合成测试通过不代表训练、GPU 或竞技表现通过。

计划的控制臂只使用原有完整候选加权交叉熵；实验臂在相同数据和训练条件下增加教师选中 `PLANT` 后、同目标不同工人候选之间的条件排序损失。教师标签和目标掩码只参与监督，不进入部署模型。条件排序不直接学习目标选择或跨操作竞争，原教师的经济门控与候选机会集仍然存在。真正控制臂必须调用 `ce_only_objective`；`combined_objective` 即使系数为零也会执行辅助路径。

`batching.py` 生成两臂共用的锚点批次：来自已认证训练集的合格组依固定随机次序选择，前两个锚点属于不同簇，遍历全部合格锚点后循环；每批其余组在排除锚点后无放回抽样。锚点有意改变自然数据分布，不能将该分布下的对照结论直接外推自然分布。资格和簇必须只从训练来源获得，批次索引与种子不公开。

`targets.py` 根据已认证的原始候选身份构造训练监督掩码，要求教师选中 `PLANT`、相同目标且至少两个不同单位；分块构造有限大小的临时掩码。`loss.py` 与 `objective.py` 使用全有效批次的两个分母，对填充及无资格行使用安全 dummy。输入有限也不保证极端 float32 运算结果有限，未来训练入口必须在更新前同步检查所有损失和梯度，并在更新后检查参数及优化器状态；否则不得宣称训练成功。

`evaluation.py` 按簇等权计算完整候选、目标加操作、条件工人排名，以及候选中确有两种以上操作时的各操作召回。每项须满足该指标自己的总组数和每簇门槛；不足或缺簇标记 `unknown`，不能当作通过。返回的精确均值只供本机使用，须另经脱敏审查才能发布。既有两类开发数据均已消费，数值未重合集不是独立对局或正式留出。

`masks.py` 要求事先固定的本地清单摘要，核对登记提交、旧／新来源顺序、每个私有掩码摘要和长度；读取 NPY 前先检查有界文件头与精确数据长度，拒绝冲突和异常格式。调用方仍须逐级认证来源登记、完整数据清单、数组、分片顺序和掩码身份；仅凭掩码长度或现场自算的清单摘要不足以绑定源数据。上次预检没有在执行当时单独封存本地掩码清单的摘要，现在才计算的摘要不能独立证明文件保持原样；后续入口须在新登记后认证来源并重新计算、比对掩码，固定新摘要再训练，另行记录这次只读复算，不能当作旧尝试的一部分。文件哈希及前后检查也不是操作系统锁。

仅运行合成回归（不使用真实数据、模型或 GPU）：

```text
python -B -I kaggriculture/learning/task_pair_training_v1/test_batching.py
python -B -I kaggriculture/learning/task_pair_training_v1/test_targets.py
python -B -I kaggriculture/learning/task_pair_training_v1/test_loss.py
python -B -I kaggriculture/learning/task_pair_training_v1/test_objective.py
python -B -I kaggriculture/learning/task_pair_training_v1/test_evaluation.py
python -B -I kaggriculture/learning/task_pair_training_v1/test_masks.py
```

JAX 已安装时，损失及目标函数的合成回归还在 CPU 检查梯度；如果依赖不存在，相关测试会明确跳过。GPU 真实训练及部署重载一致性必须由未来登记的真实执行另行证明。
