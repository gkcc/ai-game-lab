# 首个浇水分歧的完整单位请求比较

这个窄用途实验只回答：同一事实状态下，替换一个浇水任务选择后，最终按单位编号排列的全部请求是否改变。来源是此前已消费的一个历史种子、三个冻结对手、双席位的六个 step 15；不是新留出或收益实验。

保持两个模型、教师、默认 Bot、原规则和历史证据。先从每条绑定 trace 读取前 16 个物理行，前 15 行不作 JSON 解码，只解码并核对第 16 行原字节 SHA。完整 trace SHA 是继承证据，本轮不重新读取全文件计算。gzip 在前缀后主动关闭，内部未返回的缓冲量保持未知；实际底层压缩读取和返回 payload 均有独立硬限额。

两个模型各哈希、加载一次，保留部署时的 float64 与首 argmax 规则。全部六次基线调用先复现历史回调、选种、预留和完整单位请求；任何不一致都会停止干预。然后各再次执行一次：固定回调前的输入和控制器状态必须与基线完全相同，只在该处选择当前合法的条件教师 WATER 候选，随即恢复原学生，后续候选重新枚举与评分。不会将整回合教师策略替代或旧后缀回放当作单次干预。

比较历史 `unit_actions`、新基线、干预结果及各自返回的 `[farmer, *hands]`。保持单位编号、数组长度、参数和 PASS；不排序成动作多重集。trace 没有完整市场返回值，因此本轮不声称历史 market 一致，也不读取 Replay 来扩大范围。请求变化不等于官方执行变化，更不等于经济损失。

全部代码、核对器和最多四项内存协议检查先冻结并独立预审、提交。之后只执行一次连续 180 秒阶段：主工作 120 秒，独立核对至多 40 秒，最后 20 秒包含关闭及终态核验；单次原有进程关闭上限仍为 10 秒。一个 worker、单线程数值库，12 次以内真实控制器调用；每次调用检查 10 秒上限，样本对的两次活跃调用时间合计最多 20 秒，不包含中间处理其他样本的等待。模型加载阶段最多 20 秒。失败不重试、补样或扩预算。

任务头最多 90 次前向／46,080 个评分候选，作物头最多 96 次前向／480 个 logits 值。原累计任务评价 3,844／226,982 不退款。模型文件哈希读取、np.load 及 seek 后重读计入返回文件字节，最多 4 MiB；不使用输入缓存免除计数。模型前向、控制器 choices、编码、源 JSON 对象和派生收据读回分列。

独立核对器在数据读取前完成，仅读本轮至多六份小收据一次，含 primary 元数据总计最多 1 MiB，重新计算请求向量相等性、差异单位数量、唯一替换与预算。不追加原流或模型读取，不冒充第二次原始复现。相同与不同都可通过诊断验收，不能据此要求正向收益或模型晋级。

输出分为本地私有对照收据与可发布汇总。完整观测、候选坐标、单位请求向量和进程身份不公开；原始日志、旧模型和全部旧失败结论保留。内存检查不产生临时文件。不训练，不增加比赛或官方状态转移。

已有输出拒绝重复运行，唯一执行命令是：

```powershell
.venv/Scripts/python.exe -B -m learning.task_bc_first_water_unit_requests_v1.experiment run --out artifacts/task-bc-first-water-unit-requests-v1-20261026
```
