# 历史任务选择到动作影响诊断 V1

本阶段只分析已公开结果的 96 场历史比赛（8 种子、2 对手、2 席位、S/C/T 三策略）。32 个三联组形成 32 个主要 C-T 比较与 32 个次要 C-S 比较。它们不是新的独立留出样本。

登记与来源：上一阶段 `root-next-learning-decision.json`、本阶段 `registration.json`、`input-manifest.json`、`freeze.json`、独立预审及本地事前提交。原始192个 gzip 文件只解码一次，同一次压缩读取计算 SHA256；不读取模型、缓存或其他比赛，不运行 Agent、官方引擎或网络。

分析分别记录任务选择、完整请求、物理观测和终局账目。共同观测前缀内，每回合的回调在第一次完整输入或选择分歧处停止配对。物理摘要排除请求和耗时，保留两方背包字典顺序。仅有请求变化不算执行成功；后续观测和现金差只描述整条策略轨迹的关联。

保存轨迹没有明确的任务完成事件。相邻回合改派、移动请求和几何位置只作描述；完成、未完成、耗时价值及因果收益仍未知。因此，即使任务—请求—观测链覆盖率达标，也不能据此批准时长感知选项训练。分析结果允许为 `evidence_insufficient`。

固定检查：全部64对比较、96场终局账目、32场原 C-S 首次请求分歧；分歧后第1、第24状态及终局，超过719截到719；按完整种子和对手汇总，保留两席。无新 bootstrap、逐回合显著性、反事实价值标签或收益因果百分比。

运行流程为 prepare → 合成回归 → freeze → 独立预审 → 脱敏导出并本地提交 → 单次 run。执行入口要求实际事前提交身份；失败消耗尝试，不能换样本或静默放宽上限重跑。源码可用 `python -B -m unittest learning.task_action_impact_diagnostic_v1.test_analysis` 单独验证合成回归，不读取历史原始数据。

预算：单CPU分析，CPU/墙钟各30分钟，整个实现、审查与发布90分钟；子进程2GiB、父子总3GiB的外部采样监控（并非OS硬配额）。压缩读取1GiB、解码32GiB、落盘8MiB（日志最多1MiB），不保存解压副本。16MiB元数据/源码计量覆盖实际分析入口和独立复核；开发实现读码、Git对象及仅针对公开导出物的既有隐私检查另列，不进入此计数，仍计入90分钟且不能借此读取选定原始文件。

默认Bot、冻结策略/模型、官方规则与全部历史证据保持原样；没有训练、GPU前向、新对局、官方转移、BC/DAgger/PPO或自动晋级。
