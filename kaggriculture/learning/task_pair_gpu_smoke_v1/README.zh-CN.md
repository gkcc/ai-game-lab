# 两臂任务模型：合成 GPU 冒烟候选

本目录只准备一次有界的合成设备验收：从现有纯合成 fixture 构造数据和玩具参数，复用 `packing` 与 `fit_core`，同一批次喂给两臂，各做两次更新。它不读取真实示范、旧模型权重或比赛，不写模型文件，不用于判断策略收益。本目录和合成 CPU 测试本身不证明 GPU 已执行训练；真实设备尝试必须先独立审查、登记并固定源码身份、目标名称、预算及单次停止条件。

候选本身不认证 Git 或保存持久的一次性标记；正式调用者须在启动前沿用项目登记、源码身份与排他尝试收据，失败后不自动重试。所有相关源码都应列入登记，不能仅凭这里的脚本路径认为来源可信。

实际入口要求 JAX **恰好发现一个可见 GPU**，且其 `device_kind` 与调用者提供的名称完全相同；名称不写进代码或程序输出。此检查只覆盖 JAX 可见设备，不证明机器只存在一张物理显卡。两臂每步的梯度、参数与 Optax 状态的设备和同步由 `fit_core` 的实际守卫检查；两个更新、辅助梯度非零、两臂权重变化和最终分化均为通过条件。该证据不是操作系统级 GPU 活动监控，也不等于游戏环境获得 GPU 加速。本次不做 GPU 与部署推理一致性比较。

WSL 中由调用者将占位符替换为已验收虚拟环境的 Python、仓库路径及私有本机设备名称：

```text
<WSL虚拟环境python> -B -I <仓库>/kaggriculture/learning/task_pair_gpu_smoke_v1/supervisor.py --expected-device-name '<本机JAX设备名称>'
```

设备名称仅作为本机命令参数；不要把完整命令、设备名称或路径加入公开日志。`supervisor.py` 调用现有 `task_dagger_once_v1.gpu_guard.supervise`，为直接子进程建立独立 Linux 会话，约每 50 毫秒采样工作限时 120 秒，并要求子进程监管及清理阶段的耗时不超过 135 秒；监督器自身的启动、引导和收尾不计入这个门槛。在正常退出、限时或处理到取消信号时终止并检查自有进程组，再回收子进程。内层训练循环另有采样式 100 秒门槛，不是强制中断单个 GPU kernel，也不构成硬实时保证。父进程受到不可捕获的强杀或系统崩溃时，不能保证正常清理；Windows 启动者应等待 Linux 监督器确认，不应把结束 `wsl.exe` 当作清理完成。

监督器不在顶层导入训练子程序；项目依赖在原生输出静默和异常捕获范围内加载。每次监督器产生一个临时令牌，并将子进程标准输出接入非阻塞、上限 4096 字节的私有内存管道；子进程只有在设备身份、同步及两臂各两次更新都通过后发送规范收据。监督器同时要求子进程零退出、会话清理成功、管道关闭、恰有一份字段完整且令牌一致的收据；空收据、噪声、重复、溢出或写端迟迟未关闭都失败，不会等待持有写端的进程。子进程标准错误及库的意外输出不会公开；监督器只输出固定的脱敏布尔和计数。令牌仅关联本次子进程，作为本机命令参数同一用户的其他进程可能观察到它；它不是抵抗本机恶意进程伪造的认证手段。失败只输出固定阶段和白名单异常类别，不包含异常正文。`XLA_PYTHON_CLIENT_PREALLOCATE=false` 只设置在子进程环境，不修改系统或驱动。

父、子进程均须以 `-B -I` 启动，并在首次导入项目包之前执行固定 SHA 的有界引导快照。引导复用已有 initializer 检查，另外检查新包的 initializer 和同名影子模块，将 `learning` 与 `decision` 绑定到仓库目录，并在导入后核对项目模块来源；项目根不加入解释器全局搜索路径，以免影响 JAX、NumPy、Optax、jaxlib 和设备插件的延迟导入。现有合成 fixture 导入时原本会加入项目根；受控导入会抑制这条冗余插入。若解释器初始搜索路径已包含项目目录则失败。该检查不验证虚拟环境中第三方依赖的供应链，也不防任意自定义导入钩子或检查后本机进程并发替换源码；正式尝试仍须按登记前后核验所有源码及 Git 身份，且不声称有操作系统锁。CPU 测试只用显式 CPU 和虚拟设备，不应据此宣称训练已在 GPU 上运行。
