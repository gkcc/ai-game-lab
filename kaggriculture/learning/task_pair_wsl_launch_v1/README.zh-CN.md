# WSL 一次性训练启动器候选

本目录是**尚未正式登记或执行**的 WSL 启动器候选。没有有效的新登记时，它在读取本机私有合同、训练数据、旧模型或启动 GPU 前失败。启动器自身已在被解释器执行后才能自检：Windows 调用方还须在启动前独立认证该启动器、目标解释器及其登记身份。当前不提供一条声称可立即正式训练的命令。

启动器以隔离模式 `-B -I` 工作，先检查新登记 HEAD 和工作区中的登记与训练入口源码，再有界读取登记固定 SHA 的入口源码快照，调用它核对所有登记源码。之后先绑定已受检的项目导入守卫，才读取、核验事前独立固定 SHA 的本机私有合同；第三方环境门禁通过后才进行其余受信项目及 NumPy 导入。父进程和训练子进程是独立解释器，各自重新检查来源。解释器启动阶段 `.pth`／`sitecustomize`、未列明依赖和本机同用户并发替换不在此认证范围内。

启动器要求独立的本机 artifacts 根目录及之前未出现的固定监督目录。它排他创建该目录，写入含 Windows 外层预生成的本次 nonce、随机令牌及私有合同摘要的启动记录并回读，然后以合同绑定的虚拟环境原始 Python 路径启动唯一训练子进程。nonce 用于绑定本次外层与 Linux 启动记录，不能对同用户恶意进程提供认证。调用新 pidfd 监督器，只有实际观察到规定的退出、受控会话清理、规范令牌收据和时限门槛，才将原始收据的准确字节排他写入私有目录并回读。进程间管道不认证写者 PID，令牌和命令参数对同一用户本机进程并非秘密。失败时不自动重试、不覆盖已有目录或历史证据。

收到监督器通过结果后，启动器再次对本机三个模型文件分别进行有界字节快照校验和真实 `TaskNetwork(path, sha)` 重载，检查基线身份、两个新臂的来源元数据、参数差异和原有归一化；同时根据私有指标重新计算开发筛查，并与子进程记录及原始收据中的步数交叉核对。父进程未重新预测或独立计算指标。重载前后的文件检查不能代替操作系统锁，依赖运行期间没有同用户并发替换。独立重载确认文件结构和内容，筛查复算确认报告内的算术一致；它们不能独立证明子进程运行过多少梯度更新或 GPU 真实工作，这些仍是受审子进程及收据的报告。

`supervisor-result.local.json` 将技术执行与开发筛查分开：技术通过不要求开发筛查必须 passed；筛查可能为 passed、failed 或 unknown。该文件本身不证明最终外层退出与最后一次时限检查，`outer_completion_confirmation` 固定为 false，最终验收还须由 Windows 侧观察 WSL 启动器实际零退出及完整私有证据；若写完此文件后超时或取消，会另记失败，不得把这份中间结果当作最终成功。这里不运行官方游戏，不证明策略竞技提升，也不自动晋级。启动记录、令牌、收据、私有模型摘要、模型与详细开发指标均保留本机，不能发布到公开仓库。

Linux 监督器负责自己的受控会话、取消与清理；超时和资源检查均为采样而非硬实时保证。Windows 外层应无 shell 启动并等待对应的 `wsl.exe --exec` 进程；如果超时，可在本次私有监督目录创建 `cancel.request` 请求取消并等待 Linux 清理证据，不能盲杀 `wsl.exe`、终止整个 WSL 或把未收到结果当作已清理。仍无法确认时应保留原进程和产物，标记未确认并停止自动重试。会话逃逸、不可中断进程、主机崩溃及恶意同用户进程超出清理保证。

目前 Windows 和 WSL 的回归使用合成数据和注入对象：两段真实项目导入守卫在 CPU 子进程里运行，源码摘要当场生成，不能冒充正式事前登记；Windows 探针只在该子进程内移除被 WSL 门禁拒绝的虚拟环境根搜索项。监督器收据测试注入守卫结果，持久重载回归使用模拟构造器。独立复审另做一次性合成磁盘探针，在两端由原 `TaskNetwork(path, sha)` 重载三个玩具 NPZ 并检查参数、schema 和注入指标的筛查算术；探针未测试重载模型评分或磁盘损坏反例。没有访问真实训练数据或模型、运行 GPU 或游戏。正式登记、外层 Windows 生命周期和真实运行验收均未完成。
