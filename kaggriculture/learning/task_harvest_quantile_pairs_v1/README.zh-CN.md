# 收获／浇水：固定分位补采

上一轮四对单次干预已跑通，但都选择来源轨迹的第一个可用点。本阶段只在相同四条已消费来源中补充最多十二对，检验首次收获期内的回报方向和可见状态差异。不训练、不改模型、教师、默认 Bot 或官方规则。

准备阶段每条完整来源 trace 单遍扫描，校验719行、EOF、关闭和内容身份。在实际新增 HARVEST 且同单位同地点 WATER 可选的记录中，按 `(step, ordinal, unit, y, x)` 排序；若共N项，取索引 `0、(N−1)//3、2*(N−1)//3、N−1`。Q0必须认证并引用旧结果，不重新执行；Q1–Q3缺失或重复索引保留空位，不替换。

四条原始来源身份保持F01–F04；十二个运行目录和许可使用F01-Q1等唯一标识。每个新点独立从原来源分叉，复用冻结的 `task_harvest_return_pairs_v1` 选择器干预、官方恢复、执行追踪和复核 Worker。先完成H事实复现，再恰好一次把同一输入下的选择改为W；其后的选种、任务和市场可自然变化。三个单点实验不串联，收益也不能相加当成整局策略改进。

F01/F02固定为探索组，F03/F04为诊断组，按实际seed核查身份和组间隔离。它们都是已消费开发来源，四组Q0结果已公开；本轮不是新留出测试，不用16对冒充16个独立seed。

`analysis.py` 在所有新任务关闭验收后分析旧四对和新样本，最多16对。一次读取认证任务模型的metadata、mean和scale，不构造网络、不调用score；将每个H/W的275维共享状态和98维候选特征拼为373维，并按部署公式以float64归一化。最多32次行转换计入总输入行预算，另列于神经前向计数之外。保留完整结构化输入、原始H/W整对向量和归一化整对向量的精确重复/回报冲突；不以H−W差向量合并样本，不因冲突删除或重新分组。指纹和逐步输入只留本地，公开仅投影聚合结果。

入口使用游戏虚拟环境：`python -I -B runner.py prepare`；本地登记提交后，使用 `python -I -B runner.py run --registration-commit <完整提交>`。prepare认证210份既有原件、固定资产和四条来源trace，不解码Replay、不加载归一化或执行网络。运行最多十二个串行Windows Job、二十四条官方终局后缀，二十四次构造/恢复、零reset；没有从零开始的新完整比赛。720状态Replay由原来源前缀和真实官方后缀组成，验证导出不增加官方动作。

逐点精确预算为 `2*(719−step)` 次官方动作，总上限11,496；本方/对手各最多17,256次调用，含前缀历史重建。任务前向最多96,000次、选种192,000次，神经输入行与离线转换合计最多3,840,000行。每Job900秒、整个执行两小时；启动/间隔内存至少6 GiB，运行至少4 GiB，RSS/commit上限2/3 GiB，新增输出最多1 GiB。任何身份、技术、资源失败封存，无自动重试或追加点。

输出保留每点H/W的自身净利润、双方现金差、得分及目标冲突，不把单次干预回报当最优Q值或完整策略排名。训练准入始终为false。是否进入受限学习实验，必须根据本轮证据另作有界决定；现有全候选教师BC与PLANT工人排序辅助损失不能直接替代H/W回报学习。
