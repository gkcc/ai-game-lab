# 同观测任务头权重干预探针

本目录只实现一个离线敏感性检查，尚未对真实回放运行。它不训练模型、不启动官方比赛，也不能据此判断竞技收益。来源固定为已完成的单场开发冒烟及其公开证书；不能替换为正式留出赛或其他对局。

对固定的 32 个回合 `i * 718 // 31`（`i = 0..31`），从第 `k` 个状态生成合法观测，比较下一状态中保存的第 `k` 次请求。对全部 719 条追踪逐行核对步号、身份、错误状态、记录结构及预算计数；完整输入和选择仅在 32 个采样回合重新比较。随后用三个独立 `BoundedAgent` 实例恢复上一回合累计预算和历史位置，检查任务、作物闭包及 AST 注入方法属于该实例：原权重须复现请求及追踪，同权重副本为阴性对照，第三个实例仅在内存中反转任务头 `w2` 和 `b2`。第一次选择分歧之前（包括该次），检查完整有序输入相同、反转前后分数在指定容差内互为相反数；此后的输入可能因选择不同而改变，因此只统计后续选择序列与请求是否不同。平分按实际 `argmax` 行为处理；不能假定浮点计算中的偏置变化永远不影响平分。

模型只接收 `decision.api.observe` 输出的观测和配置；回放的随机种子、对方私有信息和追踪中的教师标签不会作为模型输入。输出仅含固定来源和派生参数摘要、脱敏计数及最大误差，不输出观测、动作详情、收益或随机种子。失败时不公布部分结果，现有输出目录会阻止重复运行。跨局身份由证书与完成收据绑定的回放和追踪哈希共同校验，不能只凭席位和回合号判断。

压缩输入上限：回放 4 MiB、追踪 16 MiB；解压上限：回放 128 MiB、追踪 512 MiB，追踪单行 8 MiB。这些是文件读入上限，并非进程内存硬上限。受管入口另为自有 Windows Job 设置并核对 4 GiB 提交内存上限，每次派生子进程前采样一次可用内存，要求至少 4 GiB；采样不能保证之后始终充足。独立 `verify` 命令使用一个 600 秒截止；后续 `run` 命令使用新的 600 秒截止，其内部的再次验证和运行子 Job 共用该截止，并在写成功收据前检查。父进程同步文件读写或清理若被系统无限阻塞，没有另一个外部守护进程强制终止它。内部静默仅重定向当前 CRT/Python 输出流，不能保证已经缓存的非 NUL Win32 句柄；受管入口在创建子进程时为它提供 NUL 句柄。上述检查不抵御同一用户并发篡改或任意自定义加载器。

真实运行必须先公开并冻结源代码提交 `S`，再创建仅包含本探针 `registration.json` 的直接子提交 `R`，并以 `R` 为干净工作区 HEAD。登记字段由 `run.py` 的 `_startup` 精确限定，包括来源提交、固定席位、32 个回合、输入上限、禁止重试和训练、两个运行源码 SHA256、公开冒烟证书 SHA256 和受管资源约束。登记还必须明确 `max_controller_calls=96`、`new_games=0`、`official_transitions=0`、`no_economic_evaluation=true`，并固定以下判定：至少一处同输入的首次选择不同才记 `task_choice_control_observed=true`；至少一处完整请求不同才记 `action_control_observed=true`。未出现差异只表示在这些固定样本中未观察到，不能证明模型永远没有控制能力。`passed=true` 只表示对比流程和约束通过；没有可比较分数时最大误差为 `null`。

正常调用先由独立调用方核对 `supervise.py` 的本地字节与已冻结提交一致，再使用项目虚拟环境依次执行受管预验证和唯一一次运行：

```text
python -B -I supervise.py --mode verify --source-commit <S> --registration-commit <R> --helper <standalone-helper>
python -B -I supervise.py --mode run --source-commit <S> --registration-commit <R> --helper <standalone-helper>
```

`run.py` 是内部子进程入口，它本身不证明所在 Job 或已有独立预验证；直接调用可以绕过监督合同，应使用受管入口。受管入口的自检也不能撤销它自身启动前已经执行的代码，因此调用方必须先核对其字节。参数或来源检查在持久启动标记前拒绝时，不读取真实样本且不留下尝试记录，可修正后重新进行无数据预验证；一旦预验证或运行标记创建，失败或清理不明均保留记录、不重试。

当前只有合成测试覆盖，包括临时 Git 仓库中的 `S → R` 正向及改动拒绝；它们不能证明真实来源、官方反事实执行或独立比赛已被验证。真实运行前须独立审查入口、完成登记和资源监督，不追加样本。
