# 历史证据与私有掩码的分阶段绑定

`bind_history` 接收事前独立固定的历史提交、新入口 HEAD、四份公开登记／结果原字节及本机私有收据的预先固定 SHA。它复用既有 mask recheck 的祖先、受限 Git blob 与有界工作区读取，要求旧登记→旧结果→新登记→新结果→指定 HEAD 依次为祖先，并逐份核对历史提交、HEAD、工作区和提供的原字节。它复用旧登记严格契约和公开结果的受限字段检查，同时核对旧来源 SHA 集合在新登记中未变化；不会读取私有掩码、数据或模型。

来源与分片身份、真实进程退出码、未来训练登记、全部源码和实际设备仍须由调用方独立认证。公开结果的摘要只在其 Git 原字节验证后计算；私有收据摘要必须来自此前独立固定的本机记录，不能现场用同一收据自算成预期值。返回的私有内存对象可在认证数据并确定各角色长度和 old/new 顺序后调用 `load_masks`，复用现有 `binding.load_bound_masks` 核验收据、清单和九份掩码；结果不应公开。

Git 与工作区检查只证明检查时观察到的字节，不是并发锁、独立时间戳或旧清单创建时身份证明。调用方应在使用前及结束后重新校验；该模块不证明样本独立、训练成功或游戏收益。

测试使用内存模拟的 Git 图、公开 JSON 和私有掩码，不打开真实训练数据或模型，也不使用 GPU、运行比赛或建立临时仓库：

```text
python -B -I kaggriculture/learning/task_pair_history_binding_v1/test_history.py
```
