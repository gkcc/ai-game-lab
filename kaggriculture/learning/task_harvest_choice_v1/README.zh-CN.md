# 原地甜瓜 WATER／HARVEST 可选择接口 V1

本目录是独立研究接口，保留冻结教师、模型与默认 Bot。它不训练网络，也不宣称策略收益提高。动机来自上一轮四个已消费窗口：一次收获选择足以改变后续调度和共享市场，不能让教师的单一偏好永久阻止模型表达另一种合法选择。

`HarvestChoiceAgent` 复用现有 `TaskAgent` 的固定源码钩子，仅扩展当前 callback 的候选：已有 WATER、单位可用且正站在甜瓜地块、固定官方 HARVEST 前置满足时，添加同格 HARVEST。原 WATER 保留。价格、仓容和事后收益不充当合法性门槛；教师原先强制运输等限制仍存在，所以这不是完整官方动作空间。

新增项只存在于虚拟映射。特征编码用同长度的影子任务列表替换对应动作槽；原共享特征、原候选向量及相对顺序不变。真正选中新增项后才就地替换当前原任务槽，返回原选择元组，由教师按原流程弹出任务、认领地块和消耗单位。没有事后改写完整请求，也没有往真实任务列表追加条目来意外影响雇工。

selector 只收到经过 `observe` 清理的输入副本，不看到原教师标签、优先级或 lookup。记录保留原 `teacher_label` 与实际 `chosen`，`finish` 关联最终单位请求。关闭扩展或选择原 ID 的完整请求须与旧控制器一致，包括非空采购和雇工序列；新增选项的出现本身不能改变资源预留。

官方验收固定为四个公开构造场景，每个各提交一次 WATER/HARVEST：成熟未浇水、同样成熟但仓满低价、尚未成熟、已浇水且旧教师已有 HARVEST。后两种场景各有一个不应进入候选的无效果动作，作为明确的直接边界请求验证，不冒充 Agent 的合法选择。共最多 8 次动作转移、8 次环境初始化，初始化单列；不生成完整 Replay、完整比赛、经济评价或训练标签。

用游戏虚拟环境的 `python -I -B` 执行 `runner.py prepare`；独立审查、登记并提交后再 `runner.py run --registration-commit <完整登记提交>`。两步均排他写入，正式运行一次；失败留存，不自动重试或换夹具。纯回归不创建官方环境，正式八步只能由冻结入口执行。

输入只包含公开源码、公开合成夹具以及小型默认 Bot 身份绑定；不读历史 gzip／Replay／trace、种子库存或权重。官方规则、core、JSON specification、utils 和教师字节身份固定；不修改 Server。配置中的合成初始化值属于公开机制测试，不是新留出测试种子。

资源门槛为启动／运行至少 4 GiB 可用内存、单进程最多 15 分钟、新私有产物 16 MiB，预留失败闭合空间。资源检查是协作式采样；复用既有官方微场景和执行追踪设施，不另建训练／审计平台。原始合成前后状态和追踪留在新本地目录，公开只给必要的请求选择与效果摘要。

通过只证明新增操作能经 selector 进入完整请求并由官方规则执行；没有证明模型会选择正确时机，也不自动启动 BC、DAgger 或 PPO。
