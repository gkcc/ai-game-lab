# 收获／浇水的一次选择与终局收益

上一轮冻结任务模型能实际选择新增 HARVEST，但四场历史开发对照的平均自身净收益下降。因此本轮先验证真实终局收益样本链，不训练、不改权重、默认 Bot、教师或官方规则。

从上一轮已完成的四条新比赛轨迹，分别取按 `(step, ordinal, unit, y, x)` 排序的首个实际新增收获选择，且同单位、同地点的浇水候选仍存在。支持非零回调序号。准备阶段每条轨迹只完整扫描一次，检查719行、EOF、哈希及关闭；没有目标则保留缺失，不补抽。

`selection.py` 绑定原点和实际模型输入；`policy.py` 只覆盖一次选择器返回值。H 保持原收获，W 改选浇水，原网络提议和实际选择分别记录，不改写网络输出或事后拼接整回合请求。此后的选种、派工、预留、市场请求和计算成本可自然变化。

`core.py` 每臂先通过旧 Replay 重建模型与对手历史，再用官方非空状态恢复路径续跑到719/DONE。恢复不调用 reset。H 必须复现全部719次双方请求和原模型轨迹、每步实际续跑状态（含公开／私有和背包／仓库顺序）、终局与EOF关闭；H最终证据写成功后才创建W。W在同一选择器输入上分叉，保持后续冻结双模型策略。实际执行追踪核实目标收获／浇水，不把请求当成执行。

目标同时保留终局 `margin(H)-margin(W)` 与自身净利润差，冲突显式标注。margin 是终局双方现金差，net_profit 扣各自初始现金，不能无条件把二者混同。它们是给定后续策略和对手的单次干预结果，不是最优Q值、全策略强度或教师单标签。

未来可用的 `inputs` 仅含过滤后的部署观测、候选与预留；收益放 `targets`，来源身份放 `provenance`。种子、对手身份、未来状态和终局结果不进入特征。这里只生成最多4对开发样本，`training_admission=false`，不据此训练或宣称统计显著。

`worker.py` 复用已有受限写入、流式轨迹读取、官方恢复及执行追踪。分别保存事件流和两份720状态 Replay 导出：旧来源前缀加实际官方后缀，明确不是两场从零新模拟。父进程重新验证事件及导出内容，不增加官方复演。失败原件保留，无同阶段重试。

入口为游戏虚拟环境 `python -I -B runner.py prepare`，本地登记提交后 `python -I -B runner.py run --registration-commit <完整提交>`。准备只认证145份历史原件、固定模型身份及4条来源轨迹，不解码Replay、不构造环境、不做前向。运行最多4个串行Windows Job、8个终局分支，8次构造／恢复、0 reset，官方动作精确为各例 `2*(719-start)` 之和；双方控制器各最多5752次，含历史前缀重建。

初始与间隔内存至少6 GiB、运行至少4 GiB，RSS上限2 GiB、commit上限3 GiB；每Job900秒、总计两小时，最多1 GiB新产物。新模型前向上限任务32000、选种64000、神经输入行数1280000。私有原件和执行明细留本地；公开只发布字段白名单结果、来源承诺与核验计数。强制终止造成的末次计数缺失按未知／失败，不补造零计数。
