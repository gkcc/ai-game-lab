# Windows 合成进程监督：预登记

历史训练缓存覆盖分析中的监督器只采样了 Windows 虚拟环境启动器，没有覆盖实际 Python 后代。旧分析及其资源验收未通过的结论保留。本阶段另立源码与独立目录，只用自建合成进程验证修复，不重跑该分析。

新入口先挂起创建自有启动进程，将其加入新建 Windows Job，配置关闭时终止 Job 内成员，然后恢复启动；只控制持有的进程和 Job 句柄。分配、恢复、监测或清理失败时不宣称成功。Job 成员数和各成员 RSS 从同一份列表采样；Job 提交内存与 RSS 是不同口径，RSS 求和可能重复计算共享页，采样也不是硬实时上限。

预登记两个顺序场景：先由合成工作进程申请 32 MiB 并正常退出；首场收据通过后，第二场预设申请 128 MiB，达到 80 MiB 的 Job 合计 RSS 时触发自有 Job 终止。阈值可能在工作进程完成分配前触发，因此不能单凭该场结果证明 128 MiB 已实际分配。每场只允许一次启动；超时、身份不符、无法确认清理或其他错误均停止，不再重试。两个成员的采样只能证明某次 Job 成员列表至少包含两个进程，不单独识别工作进程。

会校验项目虚拟环境的解释器身份，但公开材料只保留相对位置及摘要，不发布进程 ID、绝对路径、命令行或原始日志。此阶段不读取训练缓存、模型、回放或轨迹，不进行新比赛、训练或 GPU 运算，也不修改官方规则、默认 Bot 或系统设置。

Windows 文档说明，通常由 Job 内进程通过 CreateProcess 创建的子进程会继承 Job，但存在例外与嵌套限制；具体行为须以本机合成场景核验为准。来源：[Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。
