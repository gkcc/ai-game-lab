# 新开发种子的教师任务示范：事前登记

本阶段采集新的真实对局示范，目标是增加有限任务选择 BC 的训练状态覆盖。教师是**冻结规则任务选择器与冻结作物模型的组合**，不是完整纯规则教师；所收集的标签是候选任务选择，不证明该任务已完成或决策最优。

事前固定两个新开发种子，分别交换席位对阵冻结 `round2`，共 4 场官方完整比赛及各自 719 步主复演，最多 2,876 次实时状态转移和 2,876 次复演转移。两个席位不是独立种子；另预留两枚未用于本轮比赛的种子，未来正式比较仍须另行登记。种子排除范围及无法排除的历史缺口见登记文件。

本轮依游戏、回合、回调序号的固定哈希抽取约八分之一机会。每条源轨迹须先通过官方引擎结算、逐回合 actor 与对手重建、私有及公开状态与顺序复演，并核验对应逐场收据。所有教师记录检查教师标签与 actor 选择一致；样本至少 256 组、每开发种子至少 32 组、至少三类操作，否则停止。压缩和解码输入、候选数、工作时间及 Windows Job 采样门槛均在登记中固定；采样不是硬实时内存限制。

由于既有复演使用 Python 断言，正式比赛入口将在同一父进程检查 `sys.flags.optimize == 0` 且 `PYTHONOPTIMIZE` 不存在，再启动比赛。Windows 子进程按现有实现继承该环境并仅以 `-B` 启动；本阶段不会单独测量子进程优化标志。

数据 worker 之前，单独验证 venv 与命名 Job；新分类器先检查 Job 状态，失败时不读取缺失探针结果或启动数据 worker。任何官方执行、来源身份、资源、清理、样本或复演失败均停止，不重试、不补种。仅保留本地原始回放、轨迹和数组，公开材料只含脱敏汇总与源码身份。

若数据达标，后续另行核验旧封存训练数组 SHA，再按本次事前写定的配方将旧数据和本次数据合并，使用既有训练器固定 128 次更新；本阶段不会自动训练。改变的示范状态与样本量会混杂，不能把未来结果归因于其中某一因素。正式竞技结论须使用尚未消费的新测试种子并事前冻结完整评估；这里的标签一致也不证明泛化或收益提升。

本地 Git 登记只证明本地版本关系，并非可信第三方时间戳。旧策略、模型、默认 Bot、规则引擎和历史结果均不改写。
