# 收益归因消费者兼容性修复

基于 `c0122d9075e5e74fac3bf2fe3a1d15e755a96c84` 的复审，本轮只修复 `Attribution.sink` 的单位动作与市场订单操作码读取。没有修改官方规则、策略、默认 Bot 或历史结果，也没有进行 BC。

## 变化和计数口径

两个分支共用 `_opcode_view`：只有列表非空且首项为非空字符串时才读取操作码；其他载荷仅在计数视图中记为 `invalid`。不重写追踪事件的 `requested`、`effective` 或发给官方引擎的动作。不做动作合法性判断；未知字符串操作码仍原样保留，其结果由官方决定。

- 官方接受但无效果的空/异常单位动作，记录为 `unit:invalid:no_effect`，不计为 PASS 或成功动作。
- 官方解析器忽略的异常市场订单，保持 no_effect、零成交和零现金变化；不会虚构卖出产品。
- 合法动作的原有键、部分成交、原子 PLANT 拒绝等口径不变。例如原子拒绝后有效动作仍为 PASS、状态仍为 blocked，不能算播种成功。
- 官方自身抛出的异常继续传播，不能被新的字符串拼接异常替换，也不会被消费者吞掉。

本轮消费者计数版本为 2，记录在新冻结清单和新证书中。官方执行标签版本仍为 2，语义审计 v1/v2 哈希算法均未改变；这些是不同的版本概念。

## 回归覆盖

`verify_attribution_consumer.py` 使用安装的完整官方 Environment，经真实 ExecutionTrace 到新消费者，不仅直接调用 sink。

50 个双席位异常载荷场景覆盖农夫、实际已雇佣工人和市场订单，包括空列表、None、非列表及非字符串/空操作码。逐场比较追踪前后的完整官方状态，并确认消费者未修改事件原始载荷。另验证 PASS、未知字符串、原子种子拒绝、部分卖出、购种、收获→入库→出售链，以及原生异常继续传播。

两场新完整边界对局分别占双方位置，全局使用空农夫动作和异常市场操作码，均 720 状态、719 次转移、双方 DONE、收益 3000；回放经新消费者完整复演，空动作没有被改成 PASS。原始边界回放仅保留本地。

原有 17 项审计回归和 6 项生产边界检查通过。最初三步链路的测试对照误放在全局 hook 作用域内，导致测试失败；已改为先运行对照，再独立安装 hook，最终通过后才冻结复核代码。没有为通过测试改动策略或规则。

## 112 场新证书

`recheck_attribution_consumer.py` 采用 spawn 进程池，调用现有官方逐步复演器重新执行保留的 108 场正式赛和 4 场复现，共 80528 次官方状态转移。检查原始 gzip 哈希、双方公开/私有状态、背包顺序、v1/v2 语义摘要、最终收益及全部旧执行和归因字段。新记录用 test/repeat 明确身份，复现不纳入收益统计。

每一条新审计和归因记录均与旧证书对应行完整相等。随后用未修改的分析器，以新证书的全部正式赛指标重新生成归因结果，与旧 `attribution.json` 所有字段一致。因此本轮确认的是兼容性修复没有改变有效旧数据，不是新的策略提升或独立比赛证据。

新证书保存在 `review/evidence/attribution-consumer-repair-20261020/official-reexecution-v2.json`。它绑定新的代码冻结清单，并引用旧证书、旧冻结、旧账本和旧归因文件的原始 SHA。旧 `profit-attribution-20261019/` 中全部 488 个既有文件保持原哈希；包括默认入口在内的 13 个运行时策略/模型文件也保持不变。

原公开快照共 299 个文件。本轮授权修改旧消费者和两份进度入口，其余 296 个旧公开文件保持原哈希；所有旧证据仍在原目录。两份进度入口只追加本轮信息，不覆盖以前的结论。

## 命令与证据边界

在游戏目录中，针对性回归可独立运行到一个新的输出目录：

```powershell
.venv/Scripts/python.exe -B -X utf8 -m decision.verify_attribution_consumer --output artifacts/consumer-check/consumer-regression.json
```

全量复核需要本地保留的原始比赛目录，输出目录必须事先放置本轮 `freeze.json`、`preservation.json` 等来源文件；该目录中不能已有同名新证书：

```powershell
.venv/Scripts/python.exe -B -X utf8 -m decision.recheck_attribution_consumer --historical artifacts/profit-attribution-20261019 --output artifacts/attribution-consumer-repair-20261020
```

旧实验的冻结文件约束旧源码，不能把其中旧消费者 SHA 改成新 SHA 以绕过校验。旧审计入口保留作为历史实现；修复版采用新复核入口和新清单。复核已完成的输出再次执行会拒绝覆盖，应另备新目录。

`source-map.json` 区分实际运行时字节与公开 Git blob。两个未修改的历史依赖 `execution.py`、`full_audit.py` 在运行时为 CRLF、公开副本为 LF；归一化后逐字节相等，公开 LF 转为 CRLF 也已核对能精确恢复运行时字节。新证书继续绑定原始运行时 SHA，不替换旧哈希或为对齐行尾修改旧公开文件。在另一份公开检出上重演时，需要恢复这两个依赖的相同行尾，否则严格源码校验会拒绝运行；本机原运行目录无需变化。

公开证据只含相对路径、哈希、构造测试载荷、摘要和脱敏经济指标；不上传原始回放、日志、逐步私有状态、凭据或机器配置。外部读者不能仅凭证书独立验证未公开的原始 Replay，可以核对来源和等价性记录，或在拥有原始证据时复演。

本轮未把截断减少、任务安排和销售变化拆成独立因果利润；既有六种子、镜像对手和探索性统计限制继续适用。先不做 BC。
