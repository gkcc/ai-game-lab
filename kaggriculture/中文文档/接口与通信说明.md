# 接口与通信说明

这是对本地官方 Python 调用链、开发指南和 `kaggriculture.json` 的中文对照。返回[中文入口](README.md)。

## 本地怎样通信

本项目使用 `kaggle_environments.make("kaggriculture")`，再由 `env.run([策略0,策略1])` 推进比赛。框架每回合调用 Python 策略函数，传入观察值和配置，取得返回的动作字典，交给官方引擎执行。

```text
官方引擎 → 当前状态 observation、配置 configuration → 策略函数
策略函数 → 动作字典 action → 官方引擎 → 下一回合状态
```

本地这条路径没有需要你手动连接的网络端口，也不要求给服务器发送 HTTP 请求或自行实现标准输入输出协议。JSON 是状态、动作及回放的序列化形式；Python 中对应字典和列表。

本项目策略入口：

```python
def agent(observation, configuration):
    return {"farmer": ["PASS"], "hands": [], "market": []}
```

官方最小示例也支持只有 `observation` 一个参数的函数。不能把 Lux S3 的进程标准输入输出协议套在这个项目上。

## 输入字段完整对照

| 位置／字段 | 类型 | 中文说明 |
|---|---|---|
| observation.player | 整数 | 我方编号 0 或 1 |
| observation.step | 整数 | 框架提供的全局回合编号，从 0 开始 |
| observation.day | 整数 | 当前天数，从 0 开始 |
| observation.hour | 整数 | 当天回合，从 0 开始，默认 0～23 |
| observation.farms | 列表 | 双方公开农场，按编号索引 |
| farms[i].money | 数字 | 玩家现金 |
| farms[i].tiles | 二维列表 | 地块，必须按 `[y][x]` 访问 |
| farms[i].farmer | 两元素列表 | 主农夫 `[x,y]`，x 向右、y 向下 |
| farms[i].hands | 坐标列表 | 当天工人，顺序对应输出 hands |
| farms[i].unlocked_quadrants | 字符串列表 | 已解锁象限 NW、NE、SW、SE |
| farms[i].hires_today | 整数 | 今天已雇工次数，影响下一次价格 |
| observation.private | 字典 | 仅我方可见 |
| private.shed | 物品到数量的字典 | 仓库产品、动物、肥料等 |
| private.seeds | 作物到数量的字典 | 全体单位共用的独立种子栏 |
| private.inventories | 字典列表 | 主农夫背包在 0，其后为各工人背包 |

| observation.market.prices | 产品到价格的字典 | 当前单位售价 |

作物与动物地块的全部内部字段、含义见[游戏规则的观察数据格式](游戏规则.md#观察数据格式)。

## 输出格式与全部动作

`farmer` 是一条动作列表；`hands` 是按输入工人顺序排列的动作列表集合；`market` 是有序订单列表。默认输出为 `{"farmer":["PASS"],"hands":[],"market":[]}`。

| 指令 | 参数 | 用途 |
|---|---|---|
| NORTH／SOUTH／EAST／WEST | 无 | 上／下／右／左移动一格 |
| PASS | 无 | 等待 |
| PICKUP | 物品、可选数量，默认 1 | 仓库旁取货 |
| DROP | 无 | 仓库旁把全部背包卸货 |
| PLACE | 物品、可选数量 | 放动物；或仓库旁放指定物品 |
| PLANT | 作物 | 消耗共用种子，在脚下播种 |
| WATER | 无 | 给脚下作物浇水 |
| HARVEST | 无 | 收脚下作物或动物产品到本人背包 |
| FERTILIZE | 无 | 给脚下作物施肥 |
| BUILD_COOP | 无 | 建鹅舍 |
| BUILD_PASTURE | 无 | 建牧场 |
| DIG | 无 | 移除作物、杂草或空设施 |
| FEED | 无 | 用小麦喂脚下动物 |
| COLLECT_FERTILIZER | 无 | 收脚下动物的一份肥料 |
| CARE | 无 | 照料脚下动物 |
| BUY_SEED | 作物、数量 | 市场买种子 |
| BUY_PRODUCT | WHEAT 或 FERTILIZER、数量 | 买小麦或肥料 |
| BUY_ANIMAL | 动物、数量 | 买动物，需后续取出并安置 |
| SELL | 产品、数量 | 卖仓库里的产品 |
| HIRE | 无 | 雇一名当日工人 |
| BUY_LAND | 无 | 买下一块 5×5 土地 |

物品标识符：`WHEAT` 小麦、`CARROT` 胡萝卜、`TOMATO` 番茄、`STRAWBERRY` 草莓、`MELON` 西瓜、`GOOSE` 鹅、`EGG` 蛋、`COW` 奶牛、`MILK` 牛奶、`SHEEP` 绵羊、`WOOL` 羊毛、`FERTILIZER` 肥料。英文指令是程序协议的一部分，不能把 `WATER` 改成字符串“浇水”。

## 配置与时间限制

| 配置项 | 默认 | 含义 |
|---|---:|---|
| episodeSteps | 720 | 状态长度，含初始帧 |
| actTimeout | 1 | 单次动作调用的时间限制，秒，由框架管理 |
| boardSize | 10 | 农场宽高，接口最小 4，规则默认使用 10 |
| startingMoney | 3000 | 初始现金，最小 0 |
| maxMarketOrdersPerTurn | 10 | 每回合每人最多市场订单数，最小 1 |
| turnsPerDay | 24 | 每天回合数，最小 1 |
| shedCapacity | 100 | 非种子仓库总容量，最小 1 |
| weedSpawnChance | 0.005 | 空的已解锁地块日终生杂草概率，最小 0 |
| townShopUnlockInterval | 3 | 商店解锁间隔天数，最小 1 |
| townShopSellInterval | 4 | 商店消耗间隔回合数，最小 1 |
| townCenterSellInterval | 24 | 城镇中心消耗间隔回合数，最小 1 |
| seed | null | 可选整数种子，读取后从 Bot 可见配置清除，存到回放 info 中 |
| farmHandCostMult | 1 | 斐波那契雇工费用倍率，最小 0 |
| marketParams | {} | 各产品价格曲线的部分覆盖值 |

`remainingOverageTime` 与 `actTimeout` 是框架字段，不能简单理解为“每回合都能额外计算 60 秒”。

`marketParams` 的每个产品可覆盖 `base` 基准价、`I0` 平衡库存、`T` 校准量、`below_func` 短缺侧函数、`below_target` 短缺侧目标涨幅、`above_func` 过剩侧函数、`above_target` 过剩侧目标降幅。函数取值和完整公式见游戏规则。

## 状态、奖励与回放

游戏名 `kaggriculture`，规则定义版本 `0.1.0`，玩家数 2。双方初始状态 `ACTIVE`（行动中），正常结束为 `DONE`（已结束），最终奖励是各自现金。

回放 JSON 的 `steps` 是全部状态序列。第 0 帧是初始状态；第 n 帧的 `action` 是从第 n−1 帧走到第 n 帧时提交的动作。解释动作时必须看前一帧的起始位置、地块和库存，不能把后置状态当作执行前条件。

## 常见误区

- 农活动作先于市场订单，所以本回合买种、雇工后，要下一回合才可用新种子、新工人行动。
- 站着不动可能在播种、浇水、收获或等待，不能只看位置判断。
- 不合法动作可能静默无效果，要核对后续状态。
- 一回合同种作物请求数量超过现有种子时，这种作物的所有播种请求都取消。
- 产品在个人背包里时不能直接当作仓库库存出售。
- 雇工每天重新计数，“工1”只在当天具有连续身份。
- 官方随机 Bot 的动作不由游戏种子完整控制；本地固定种子复现检查采用确定性策略。
