# 新版协调器：预算兼容修复与单场开发冒烟

本次只提交源码和合成验证，尚未登记或运行 v3 比赛。先前面板的 `ValueError` 没有保留原异常栈；在真实旧输出预算中的合成调用表明，新版官方身份检查使用可写空设备可能被预算拒绝，这与原失败现象高度一致，但不是原失败原因的直接证明。v3 改用标准错误并入已捕获的标准输出，继续校验固定官方上游提交、规则、loader 和 core，不降低旧输出预算。

运行前需绑定两批失败面板的历史凭证及其各自四个已保留种子角色。新登记前排除可识别历史；动态复扫在比赛边界重新检查。历史范围不包含已删除、外部或无法识别的记录；本地承诺也不是第三方时间戳。原失败记录不追认、不补跑、不比较部分经济结果。

启动器在创建启动标记或派生进程之前，用标准库检查历史冻结的 309 个本地文件和 23 个补充冻结的运行源码（含复用的旧源码）；补充源码与公开父提交、登记提交及本地文件逐字节绑定。历史本地与公开文件的行尾存在已记录差异，分别按对应冻结口径检查。Bootstrap 在导入前检查项目命名空间、初始化文件及可能遮蔽冻结源码的同名包和模块。直接启动器本身的调用方须先确认其可信字节；这些检查不防同用户并发修改、任意自定义加载器或全部第三方依赖变化。

准备入口要求登记实际子进程或 Windows 虚拟环境直接父启动器的 PID 和创建身份，且进程属于某个 Windows Job；Job API 不单独证明其属于指定 Job。公开预审的检查项使用受控代码，代理标识限制格式，种子和盐须在写出前检查。若无法确认临时目录清理，本地恢复信息可能包含路径，不能发布。文件链接的防护有模拟回归，本机普通权限下没有完成真实文件链接测试。

## 下一步的受控冒烟

四个开发角色的值已在源码中公开，使用前仍须确认与可识别历史不冲突，并在冒烟结束后另行登记这些角色供未来排除。只计划使用其中第一角色，对 `round2` 在先手运行一个合并任务模型对局。旧协议的内部标签仍含 `holdout`，这场是公开开发冒烟，不能作为留出测试或竞技表现的证据。

合同允许最多一场官方对局及一次同引擎主复演，成功条件为 720 个状态、719 次动作、双方 `DONE`、无错误和 719 次主复演转移一致；不允许额外复演、部分评分、失败重试或自动晋级。失败时实际转移可能部分完成或未知。旧 Worker 会在本机生成并校验逐场经济账目，但本冒烟不做收益比较、聚合或策略选择，也不公开原始回放和私有逐步状态。

计划先冒烟，再准备独立正式面板。若反过来先准备 formal，其排除快照可能使之后的冒烟被历史扫描保守拒绝；这本身不证明开发角色曾被实际使用。任何未来正式测试都必须另用新种子、事前冻结配置并独立审查。

本轮 138 项隔离回归通过，包含合成 Git 直接子提交、真实 Windows 轻量 Job、预算内身份检查、历史角色隔离和入口拒绝反例。全套结束后仅纠正 bootstrap 首行说明及等价改写测试中的合成路径字面量，并对准备入口重新跑针对性回归。另有独立子代理复核私有准备工具和源码；合成比赛及账本替身不等于真实官方对局验收。没有重新训练、修改默认 Bot、修改官方规则或覆盖历史证据。
