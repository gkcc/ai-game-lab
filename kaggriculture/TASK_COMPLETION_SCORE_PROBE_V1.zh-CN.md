# 已观察任务分歧的单次模型排序核对

先前事后诊断发现：同一个已选配对的第 2 步，模型与教师在相同输入下都选种植任务，但分配了不同工人。本阶段只核对冻结模型在这个 callback 上的排序，不重新训练，也不运行新比赛或官方复演。

由于上阶段没有保存 callback 序号，需要比较候选局与教师局两份已验证 trace 才能确定首个相同输入的选择分歧。两份 trace 各流式完整解码一次，以核对整文件 SHA 和行数；只对第 2 回合的 JSON 行进行解析，其他回合内容不进入模型。若在首个选择差异前输入先不同，或者无法重现已登记的分歧，立即停止，不挑后面的案例。

在模型身份及输入 schema 核对通过后，对该回调完整候选集最多运行一次 CPU 前向，上限 8,192 行；验证所有分数有限，并按冻结的“精确并列取候选原序第一个”规则重现原模型选择。公开结果只含候选数、教师选择的模型排名、两选择的分数差、同分情况及是否同一目标，不含候选 ID、坐标、工人身份、特征向量或逐条分数。

两份 trace 的压缩输入上限 128 MiB、解码上限 1 GiB、单行上限 16 MiB；300 秒在流块和各处理阶段检查，单次解压或解析不可抢占。模型加载后与前向后再次核对哈希，只能发现持续变化，不能排除中间瞬时替换后恢复。任何身份、大小、分数、顺序或预算失败即停止并保留部分计数，不重试。

该回调由已观察的经济结果事后选出，不是独立留出。模型分数只能说明此输入下的排序，不证明某项特征导致排序、不证明工人分配造成收益差，也不能代表模型整体能力。原始 trace、模型权重和个人配置留在本地；旧证据、默认 Bot 与官方规则保持不变。

## 实际结果

事前提交 `7d4c5821617203313ec67b0ce1cae7faafe18e72`。两份固定 trace 各完整流式解码一次并验证 SHA，各自只解析第 2 回合；在原始顺序上找到相同输入下的首个选择差异。一次 CPU 前向成功重现原模型选择，模型加载后和前向后的哈希均匹配；没有 GPU 前向、新比赛、官方复演或训练。

该 callback 有 144 个候选，模型选择排名第 1，教师选择在同一个模型评分中的排名为第 5；模型选择的分数高约 0.9856，两者并非精确同分，且指向同一目标。结合上阶段记录，两种选择对应不同工人、同一目标的种植任务。分数是模型的排序值，不是经校准的收益预测。

独立子代理核对了源码、排名规则和聚合收据，但没有读取真实 trace、模型、特征或逐条分数，也没有再次推理。这个结果只能描述一个按经济结果事后选出的 callback；不能证明哪些特征造成排序，不能证明工人选择造成收益下降，也不能评估模型一般强弱。原始 trace、权重、候选身份、特征和逐条分数均留在本地。
